## 1. 项目背景与目标

### 1.1 背景

平台已接入 Polymarket 预测交易功能，用户通过任意资产（加密货币或充值法币）在平台下单，由平台的冷钱包调用 Polymarket CLOB 合约以 USDC.e 执行交易。

当前存在的资金管理问题：
- **内部账本**记录的是用户余额、冻结金额、平台收入等
- **冷钱包**持有链上 USDC.e 余额和 Outcome Token 持仓
- **Polymarket** 有已成交订单和未结算持仓
- **三个系统各自独立**，缺少统一的对账验证机制

### 1.2 业务目标

1. **资金安全**：每日自动验证内部账本总负债 = 冷钱包 USDC.e 余额 + Polymarket 持仓价值
2. **异常发现**：自动检测内部账本与链上数据的不一致，支持 4 类异常处理策略（自动修复/等待重试/暂停人工/取消退款）
3. **操作闭环**：对账异常 → 判定处理 → 操作执行 → 记录留痕 → 通知用户 的完整闭环
4. **监管合规**：完整的对账记录、操作日志、审批链路，满足审计要求

### 1.3 成功指标

| 指标 | 目标值 |
|------|--------|
| 余额级对账成功率 | ≥ 99.5% |
| 异常发现到自动化处理时间 | < 5 分钟 |
| 人工介入异常的处理时效 | < 4 小时 |
| 对账覆盖范围 | 100%（所有冷钱包地址 + 所有 Polymarket 市场） |
| 误报率（错误触发异常） | < 1% |

## 4. 功能需求详情

### 4.1 对账总览 Dashboard

#### 4.1.1 核心数据展示

| 数据项 | 数据来源 | 刷新频率 |
|--------|---------|---------|
| 内部账本总负债 | DB 聚合查询 | 实时 |
| 冷钱包 USDC.e 余额 | Polygon RPC | 每 5 分钟 |
| Polymarket 持仓估值 | CLOB API | 每 5 分钟 |
| 对账差额 | 计算得出 | 每次对账后 |
| 待处理异常数 | 异常表统计 | 实时 |
| 上次/下次对账时间 | 对账批次表 | 实时 |

#### 4.1.2 对账趋势图

- X 轴：时间（最近 7 天/30 天）
- Y 轴：金额（USDC.e）
- 三条曲线：内部账本负债 / 冷钱包余额 / 持仓估值
- 标注每次异常发生的时间点

#### 4.1.3 异常告警面板

- 按严重程度分颜色：🔴高/🟡中/🟢低
- 显示异常类型、发现时间、关联订单
- 支持一键跳转到异常处理页

### 4.2 对账批次管理

#### 4.2.1 批次列表

| 字段 | 说明 |
|------|------|
| 批次号 | 格式 REC-YYYYMMDD-HHMMSS |
| 对账类型 | 余额级 / 交易级 / 持仓级 |
| 执行时间 | 开始时间 |
| 状态 | 通过 / 异常 / 失败 / 运行中 |
| 差额 | 正负差额 |
| 操作 | 查看详情 / 重新对账 / 导出 |

#### 4.2.2 批次详情

- 对账时间、耗时
- 内部账本总负债明细（用户余额 + 冻结金额 + 平台收入）
- 冷钱包余额明细（按地址展示）
- 持仓估值明细（按市场展示）
- 异常列表（如有）

### 4.3 异常管理中心

#### 4.3.1 异常列表

| 字段 | 说明 |
|------|------|
| 异常 ID | 系统生成 |
| 异常类型 | balance_mismatch / amount_mismatch / order_status_mismatch / position_mismatch / settlement_mismatch / missing_onchain_tx / missing_ledger_tx / duplicate_tx / unresoled_order / stale_position |
| 严重程度 | critical / high / medium / low |
| 所属象限 | Ⅰ自动修复 / Ⅱ等待重试 / Ⅲ暂停人工 / Ⅳ取消退款 |
| 关联订单 | 关联的业务订单 ID |
| 关联用户 | 关联的用户 ID |
| 发现时间 | 异常发现时间 |
| 状态 | open / investigating / resolved / ignored |
| 处理人 | 负责处理的管理员 |

#### 4.3.2 异常处理流程（四象限策略）

**象限Ⅰ - 自动修复**：
- 系统自动执行修复操作
- 记录到 anomaly_action_logs
- 不通知用户，不产生工单

**象限Ⅱ - 等待重试**：
- 标记为 pending，设置超时阈值（默认 1h）
- 下轮对账自动重试
- 超时后升级为象限Ⅲ或Ⅳ

**象限Ⅲ - 暂停人工**：
- 自动冻结关联用户账户出金
- 发送通知给资金专员/风控主管
- 人工核查后可选择：重新执行/取消退款/忽略
- 操作需要风控主管审核

**象限Ⅳ - 取消退款**：
- 自动取消订单，全额退款
- 发送通知给用户
- 记录操作日志

#### 4.3.3 异常操作界面

每个异常详情页面包含：
- 异常摘要（类型、时间、严重程度）
- 关联数据对账（内部账本 vs 链上 vs Polymarket）
- 关联订单信息（用户 ID、订单 ID、金额、状态）
- 处理操作区（自动修复/标记人工/取消退款/忽略）
- 处理备注输入框
- 操作历史记录

### 4.4 交易明细对账视图

三方交叉比对（内部账本 | 冷钱包链上交易 | Polymarket 成交）：

- 支持按时间范围筛选
- 支持按匹配状态筛选：已匹配 / 仅内部 / 仅链上 / 金额不符 / 待确认
- 每条记录显示：三方各自的状态和金额
- 支持批量手动匹配
- 支持导出 CSV

### 4.5 业务订单异常状态映射

| 对账异常类型 | 订单状态 | 用户端展示 | 用户可操作 |
|------------|---------|-----------|-----------|
| 无异常 | filled / settled | 正常 | 可查看 |
| 自动修复 | partially_filled | 显示实际成交数量 | 可查看 |
| 等待重试 | processing | 「处理中，请稍候」 | 不可操作 |
| 暂停核查 | risk_review | 「风控审核中，请联系客服」 | 联系客服 |
| 确认取消 | cancelled | 「已取消」+ 原因 + 退款金额 | 可重新下单 |
| 市场关闭 | market_closed | 「市场已关闭，资金已自动退还」 | 可查看 |

### 4.6 告警通知

| 告警规则 | 触发条件 | 通知渠道 | 响应 SLA |
|---------|---------|---------|---------|
| 余额偏差 | 第一级差额 > 10 USDC.e | 钉钉/企微 + 邮件 | 1h |
| 交易不匹配 | mismatch > 50 USDC.e | 邮件 + 后管通知 | 4h |
| 持仓偏差 | 持仓数量不一致 | 邮件 | 当天 |
| 连续异常 | 同一异常连续 3 次 | 电话（值班运维） | 1h |
| 结算异常 | 已结算未处理 > 24h | 邮件 + 后管 | 当天 |
| 冷钱包余额不足 | USDC.e < 10000 | 邮件 | 1h |

## 5. 非功能需求

### 5.1 性能需求

| 指标 | 要求 |
|------|------|
| 余额级对账执行时间 | < 30 秒 |
| 交易级对账执行时间 | < 5 分钟 |
| 持仓级对账执行时间 | < 2 分钟 |
| 页面加载时间 | < 2 秒 |
| 并发用户数 | ≥ 50 |

### 5.2 数据一致性

- 对账操作必须幂等：重复执行不产生副作用
- 冷钱包交易记录以 tx_hash 为唯一标识
- 内部账本流水必须记录 onchain_tx_hash 或 polymarket_order_id
- 链上交易等待 12 个区块确认后再记账

### 5.3 安全性

- 敏感操作（取消订单、冻结/解冻、退款）需要二次确认
- 暂停类异常需风控主管审核
- 所有操作记录完整操作日志
- 冷钱包私钥管理独立于对账系统

### 5.4 可用性

- 系统 7×24 小时运行
- 对账失败可自动重试 3 次
- 第三方 API（Polymarket/Polygon RPC）不可用时不影响已有对账数据查看

## 7. 交互设计说明

### 7.1 页面结构

```
后管 → 资金管理 → 对账中心
  │
  ├── 对账总览 Dashboard
  ├── 对账批次管理
  │   ├── 批次列表
  │   └── 批次详情
  ├── 异常管理中心
  │   ├── 异常列表
  │   └── 异常详情 / 处理
  ├── 交易明细对账
  ├── 资金流向分析
  └── 设置
      ├── 告警规则配置
      ├── 钱包地址管理
      └── 操作日志
```

### 7.2 关键交互流程

**异常处理流程**：
1. 对账系统发现异常 → 自动分类到四象限
2. 象限Ⅰ/Ⅱ：系统自动处理，记录日志
3. 象限Ⅲ/Ⅳ：生成异常单 → 通知资金专员 → 人工处理/审核 → 闭环
4. 所有操作记录到 anomaly_action_logs

**手动触发对账流程**：
1. 运维点击「手动触发对账」
2. 选择对账类型（余额/交易/持仓）
3. 系统执行对账
4. 显示对账结果（通过/异常）
5. 如有异常跳转到异常处理页

## 9. 风险与假设

### 9.1 风险

| 风险 | 概率 | 影响 | 应对方案 |
|------|------|------|---------|
| Polymarket API 限流/不稳定 | 中 | 高 | 多节点 fallback + 本地缓存 |
| Polygon 网络拥堵/重组 | 低 | 中 | 等待 12 区块确认 |
| 冷钱包私钥问题 | 极低 | 极高 | 多重签名 + 独立于对账系统管理 |
| USDC.e 与原生 USDC 混淆 | 低 | 中 | 统一资产列表，强校验 |
| 对账时间窗口不一致 | 中 | 低 | UTC 统一 + ±5 分钟窗口 |

### 9.2 假设

- Polygon RPC 节点稳定可用
- Polymarket CLOB API 提供完整查询接口
- 内部账本已具备完整的流水记录
- 冷钱包操作记录可通过链上交易回溯
- 团队有至少 1 名了解 Polygon/Polymarket 的开发人员
