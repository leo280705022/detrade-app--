# PRD：Telegram Mini App & Bot 产品方向方案

## 文档信息
- **版本**: v1.0
- **日期**: 2026-07-01
- **状态**: 调研完成，初稿
- **目标**: 制定 All-in TG Mini App 和 TG Bot 的完整产品方案，覆盖技术迁移评估、功能规划、增长策略和团队协作

## 一、战略背景与方向

### 1.1 当前现状

| 维度 | 现状 |
|------|------|
| **产品形态** | 通过打包 H5 页面 SDK 在 TG 发布 Mini App |
| **社区建设** | 已创建 TG 社区和 Bot，但功能不完善 |
| **Bot 菜单** | 对话页面无菜单功能，交互逻辑缺失 |
| **核心业务** | 1. 交易（futures、updown、highlow、spread、taptrading）<br>2. 预测交易（接入 Polymarket 事件，代用户下单） |

### 1.2 公司战略方向

1. **大规模接入第三方** — 拓展数据源和交易品类
2. **在 TG 扩张** — 依托 Telegram 10 亿月活用户池
3. **广告投放 + 心流体验** — 打造用户沉浸式交易体验
4. **App 增长** — 多渠道用户获取和留存

### 1.3 TG 平台核心想法

- TG 原生体验优化
- 奖励功能体系
- Mini App 加载速度优化
- TG 内部用户交互逻辑
- 代理和广告投放入口

### 1.4 为什么 All-in TG Mini App

| 维度 | 数据支撑 |
|------|----------|
| **用户规模** | Telegram 月活突破 **10 亿**，约 **5 亿用户** 每月与 Mini App 交互 |
| **转化效率** | Mini App 转化率比传统 iOS/Android 应用高 **5-7 倍** |
| **获客成本** | 社交裂变获客成本接近 **$0**，远低于应用商店 $2-10/安装 |
| **生态闭环** | TON 成为 TG 独家区块链基础设施，支付-空投-Staking 闭环 |
| **竞品验证** | Hamster Kombat 3 亿用户、Notcoin 3500 万用户、Bybit 全面布局 |

## 二、TG Mini App 技术迁移方案

### 2.1 当前方案 vs 原生方案对比

| 维度 | 当前（H5 封装） | 目标（TG 原生 Mini App） |
|------|-----------------|--------------------------|
| **技术栈** | H5 页面 + SDK 打包 | React/Vue + `telegram-web-app.js` SDK |
| **运行环境** | 独立 WebView 容器 | Telegram 原生 WebView |
| **认证方式** | 自有认证系统 | Telegram initData 签名验证（HMAC-SHA256） |
| **支付系统** | 第三方支付 | Telegram Stars + TON Connect + 法币入口 |
| **主题适配** | 固定主题 | 自动适配 TG 明暗主题 |
| **设备能力** | 有限 | 触觉反馈、QR 扫描、生物识别 |
| **分发方式** | 需应用商店 | Bot 链接/菜单按钮直接启动 |
| **审核周期** | App Store 1-7 天 | TG 审核 1-3 天 |
| **更新发布** | 需重新审核 | 服务器端即时更新 |

### 2.2 迁移成本评估

#### 工作量拆解

| 阶段 | 工作量 | 关键任务 |
|------|--------|----------|
| **SDK 集成** | 1-2 周 | 引入 `telegram-web-app.js`，适配 TG 主题变量 |
| **认证重构** | 3-5 天 | 从自有认证切换到 Telegram initData 验证 |
| **支付接入** | 1-2 周 | 接入 Telegram Payments / TON Connect |
| **UI 适配** | 1 周 | 响应式调整，支持 TG 明暗主题，安全区域适配 |
| **Bot 联动** | 3-5 天 | Deep Link、Start Parameter 传递 |
| **测试调优** | 1-2 周 | 多设备测试，性能优化（首屏 < 1.5s） |
| **总计** | **4-7 周** | 中等复杂度应用 |

#### 成本估算

| 应用复杂度 | 成本范围 | 说明 |
|-----------|---------|------|
| 简单应用 | $5K-$15K | 纯展示+基础交易 |
| 中等复杂度 | $15K-$40K | 含实时赔率、持仓管理 |
| 复杂应用（含 Web3） | $40K-$80K | 含 TON Connect、钱包集成 |

#### 迁移风险

| 风险 | 等级 | 应对措施 |
|------|------|----------|
| WebView 兼容性（Android/iOS 差异） | 中 | 多设备矩阵测试 |
| initData 签名验证复杂度 | 低 | 参考官方 SDK 示例 |
| 支付通道切换影响用户体验 | 高 | 灰度发布，保留旧通道兜底 |
| 性能不达标（首屏 > 3s） | 中 | JS 包 < 100KB，关键 CSS 内联 |

### 2.3 性能优化目标

| 指标 | 当前（H5 封装） | 目标（原生 Mini App） |
|------|-----------------|----------------------|
| 首次加载 | 3-5 秒 | < 1.5 秒 |
| 交互响应 | 300-800ms | < 200ms |
| 动画流畅度 | 30-45 FPS | 60 FPS |
| JS 包大小 | 未优化 | < 100KB (gzip) |

**关键优化手段：**
- 合并 API 请求，使用 `/api/init` 端点返回首屏所有数据
- 图片使用 WebP/AVIF 格式，单张 < 250KB
- CSS transforms 替代 top/left 进行动画
- 骨架屏先渲染，数据异步加载

### 3.2 Bot 与 Mini App 联动设计

#### 3.2.1 Deep Link 参数传递

| 场景 | 链接格式 | 参数说明 |
|------|---------|---------|
| 推荐引流 | `t.me/bot?start=ref_user123` | 记录推荐关系 |
| 交易跳转 | `t.me/bot?startapp=trade_event_123` | 打开指定比赛交易页 |
| 赛事详情 | `t.me/bot?startapp=match_fifa_001` | 打开指定比赛详情 |
| 持仓查看 | `t.me/bot?startapp=position_abc` | 打开指定持仓详情 |

#### 3.2.2 联动场景

```
场景 1：Bot 推送 → Mini App 交易
  Bot 推送比赛信号 → 用户点击 Inline Button → 打开 Mini App 交易页面
  startapp=trade_BRA_vs_GER → Mini App 读取参数 → 直接展示交易面板

场景 2：Mini App 操作 → Bot 通知
  用户在 Mini App 下单 → Bot 推送成交通知 → 含持仓详情和止盈止损按钮

场景 3：Bot 对话 → Mini App 功能
  用户输入 /trade → Bot 展示热门市场 → 点击打开 Mini App 深度交易
```

### 3.3 Bot 核心功能模块

#### 模块一：交易信号推送

| 功能 | 说明 |
|------|------|
| **鲸鱼追踪** | 追踪 Top 0.5% 钱包行为，实时推送大额交易 |
| **AI 信号** | 基于赔率变化、交易量异动的智能分析 |
| **价格警报** | 用户设定目标价格，触发即时推送 |
| **赛事提醒** | 比赛开始前 30 分钟推送，含当前赔率 |

#### 模块二：快捷交易

| 功能 | 说明 |
|------|------|
| **一键交易** | Inline Keyboard 直接买入/卖出，无需跳转 Mini App |
| **跟单交易** | 跟随鲸鱼钱包自动复制交易 |
| **限价单** | Bot 内设定目标价格，到达自动执行 |

#### 模块三：资产管理

| 功能 | 说明 |
|------|------|
| **余额查询** | `/wallet` 查看资产总览 |
| **充值** | 生成充值地址 / P2P 入口 |
| **提现** | 快速提现到外部钱包 |
| **盈亏统计** | 每日/每周 P&L 汇总推送 |

#### 模块四：社交裂变

| 功能 | 说明 |
|------|------|
| **推荐返佣** | 专属推荐链接，三级分销 |
| **排行榜** | 预测准确率排名、交易量排名 |
| **群组交易** | 群组内发起预测挑战 |

### 3.4 Bot 技术架构

#### 推荐架构

```
Telegram Server → HTTPS POST (Webhook)
    → Nginx 反向代理
    → 消息队列 (Kafka/RabbitMQ)
    → Worker Pool (业务逻辑)
    → Redis (状态管理/去重)
    → PostgreSQL (持久化)
    → sendMessage API 响应
```

#### 关键技术选型

| 组件 | 推荐方案 | 说明 |
|------|---------|------|
| **接入方式** | Webhook（非 Long Polling） | 毫秒级推送，支持水平扩展 |
| **消息队列** | Kafka / RabbitMQ | 解耦接收与处理，防 Webhook 超时 |
| **状态管理** | Redis + TTL | 对话状态机，自动过期 |
| **幂等处理** | Redis 记录 update_id | 防止 Telegram 重试导致重复 |
| **监控** | Prometheus + Grafana | Webhook 延迟、队列速率 |

#### Bot 框架选择

| 语言 | 框架 | 特点 |
|------|------|------|
| **Node.js** | Telegraf / grammY | 与前端同语言，异步性能好 |
| **Python** | Aiogram 3.x | FSM 状态机成熟，社区活跃 |
| **Go** | telebot | 高并发性能最优 |

### 4.2 用户交互逻辑设计

#### 4.2.1 新用户 Onboarding 流程

```
打开 Mini App
  → Telegram 一键授权（自动获取用户信息）
  → 欢迎页面（3 秒产品介绍）
  → 引导充值（新用户奖励 $5 USDT）
  → 推荐热门赛事（世界杯冠军预测）
  → 首笔交易引导（$1 体验）
  → 邀请好友（获得额外奖励）
```

#### 4.2.2 核心交易流程

```
浏览市场（Games/Props Tab）
  → 选择赛事/市场
  → 选择盘口类型（Moneyline/Spread/Total）
  → 点击赔率按钮
  → 弹出交易面板
     ├── 市价单：确认数量 → 一键买入
     └── 限价单：设定价格+数量 → 挂单等待
  → 成交通知（Bot 推送）
  → 持仓追踪（实时更新盈亏）
  → 赛事结束 → 自动结算 → Bot 推送结果
```

#### 4.2.3 关键交互原则

| 原则 | 实现方式 |
|------|---------|
| **3 秒规则** | 首屏加载 < 3 秒，骨架屏先渲染 |
| **一键操作** | 核心交易路径最多 3 步完成 |
| **即时反馈** | 触觉反馈（Haptic Feedback）确认操作 |
| **渐进披露** | 先展示核心功能，高级功能通过二级菜单 |
| **容错设计** | 误操作可撤回，确认弹窗防误触 |

## 五、增长策略

### 5.1 代理（Affiliate）系统

#### 5.1.1 三级分销模型

```
用户 A（一级）
  ├── 推荐用户 B（二级）→ A 获得 B 交易手续费 20% 返佣
  │   └── 推荐用户 C（三级）→ A 获得 C 交易手续费 5% 返佣
  │       └── B 获得 C 交易手续费 15% 返佣
  └── 推荐用户 D（二级）→ A 获得 D 交易手续费 20% 返佣
```

#### 5.1.2 代理系统实现

| 功能 | 说明 |
|------|------|
| **专属链接** | `t.me/bot?start=ref_userID` |
| **实时统计** | 推荐人数、返佣金额、提现记录 |
| **自动结算** | Telegram Stars 或 USDT 自动到账 |
| **代理面板** | 多级下线数据、转化率、活跃率 |
| **素材库** | 推广海报、文案模板、教程视频 |

#### 5.1.3 代理激励

| 层级 | 条件 | 额外奖励 |
|------|------|---------|
| 青铜代理 | 推荐 10 人 | 基础返佣 |

### 5.2 广告投放策略

#### 5.2.1 投放渠道

| 渠道 | 成本 | 适合阶段 |
|------|------|---------|

## 十一、总结与建议

### 核心建议

1. **立即启动 Bot 菜单配置** — 零成本，快速提升用户体验
2. **分阶段迁移 Mini App** — 先核心功能，后增长功能，4-7 周完成
3. **深度整合 TON 生态** — 利用独家区块链地位，构建支付-空投-Staking 闭环
4. **社交裂变优先** — 邀请返佣 + 任务系统，获客成本接近 $0
5. **交叉推广为主** — 频道互换成本是官方广告的 1/18
6. **Bot + Mini App 联动** — Bot 做触达和快捷操作，Mini App 做深度交易
7. **鲸鱼信号 + AI 是差异化** — Polymarket 生态已验证"追踪聪明钱"的需求

### 优先级排序

```
P0（立即做）：Bot 菜单配置 + 基础命令 + 欢迎流程
P1（1 个月内）：Mini App 原生迁移 + 交易闭环 + 明暗主题
P2（2 个月内）：邀请返佣 + 任务系统 + 排行榜
P3（3 个月内）：鲸鱼追踪 + AI 信号 + 跟单交易
P4（持续迭代）：代理系统 + 广告投放 + 社区运营
```
