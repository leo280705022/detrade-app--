# 用户层级指标与数据来源映射表 (User Tier Metrics & Data Sources)

## 1. 核心层级定义回顾

*   **S 级 (鲸鱼/VIP)**: 高净值、高贡献、高忠诚。
*   **A 级 (主力/Core)**: 稳定交易、稳定入金、未来增长点。
*   **B 级 (散户/Retail)**: 高频小额、情绪化交易、易流失。
*   **C 级 (低质/Risk)**: 羊毛党、零资产、潜在风控对象。

---

## 2. 详细指标拆解与数据来源

### 2.1 S 级 (鲸鱼用户) - *关注“资产沉淀”与“利润贡献”*

| 核心指标 (Metric) | 定义/计算公式 | 数据来源 (Data Source) | 获取字段示例 |
| :--- | :--- | :--- | :--- |
| **资产规模 (AUM)** | `SUM(钱包余额 + 未结盈亏)` | **钱包系统 (Wallet)** | `wallet_balance`, `unrealized_pnl` |
| **净入金 (Net Deposit)** | `累计充值 - 累计提现` | **支付/财务系统** | `total_deposit`, `total_withdraw` |
| **手续费贡献 (Fee Contribution)** | `累计交易手续费 + 资金费率支出` | **撮合/结算系统** | `trading_fee`, `funding_fee_paid` |
| **持仓时长 (Holding Period)** | 平均持仓时间 | **订单系统** | `position_open_time`, `position_close_time` |
| **VIP 等级** | 当前 VIP Level (1-10) | **用户中心** | `vip_level` |

*   **判定标准示例**: AUM > 50,000 U **且** 月手续费贡献 > 500 U。

### 2.2 A 级 (主力用户) - *关注“活跃度”与“留存率”*

| 核心指标 (Metric) | 定义/计算公式 | 数据来源 (Data Source) | 获取字段示例 |
| :--- | :--- | :--- | :--- |
| **交易频次 (Frequency)** | 周均开仓次数 | **订单系统** | `order_count_weekly` |
| **活跃天数 (Active Days)** | 过去 30 天登录并有操作的天数 | **行为日志 (埋点)** | `login_days_30d`, `action_log` |
| **复充率 (Redeposit Rate)** | `充值次数 > 1` 的用户 | **支付系统** | `deposit_count` |
| **产品覆盖度 (Product Usage)** | 是否使用过 2 种以上功能 (如合约+理财) | **各业务模块** | `has_futures_trade`, `has_earn_staking` |
| **邀请人数 (Referral Count)** | 有效邀请下级人数 | **代理/推荐系统** | `valid_referral_count` |

*   **判定标准示例**: 周交易 > 5 次 **且** 过去 30 天活跃 > 10 天 **且** 累计充值 > 1,000 U。

### 2.3 B 级 (散户用户) - *关注“情绪指标”与“转化潜力”*

| 核心指标 (Metric) | 定义/计算公式 | 数据来源 (Data Source) | 获取字段示例 |
| :--- | :--- | :--- | :--- |
| **杠杆偏好 (Leverage Pref)** | 平均开仓杠杆倍数 | **订单系统** | `avg_leverage` |
| **最大回撤 (Max Drawdown)** | 历史最大亏损幅度 (用于判断是否需要安抚) | **账户快照/结算** | `max_equity_drawdown` |
| **体验金消耗 (Bonus Usage)** | `体验金交易额 / 总交易额` | **营销/钱包系统** | `bonus_trading_volume` |
| **爆仓次数 (Liquidation Count)** | 累计强平次数 | **风控/强平引擎** | `liquidation_count` |
| **入金意愿 (Deposit Intent)** | 点击“充值”页但未支付的次数 | **行为日志 (埋点)** | `click_deposit_page`, `payment_cancel` |

*   **判定标准示例**: 平均杠杆 > 20x **或** 爆仓次数 > 1 **或** 账户余额 < 100 U。

### 2.4 C 级 (低质/风控用户) - *关注“异常特征”与“成本控制”*

| 核心指标 (Metric) | 定义/计算公式 | 数据来源 (Data Source) | 获取字段示例 |
| :--- | :--- | :--- | :--- |
| **薅羊毛指数 (Abuse Score)** | `赠金收益 / 自有资金收益` | **风控/营销系统** | `bonus_profit_ratio` |
| **资金停留时间 (Retention Time)** | `提现时间 - 充值时间` (秒级快进快出) | **支付/风控系统** | `deposit_time`, `withdraw_time` |
| **设备关联数 (Device Link)** | 同一设备 ID 登录的账号数量 | **安全/指纹系统** | `device_fingerprint_count` |
| **KYC 状态** | 是否实名、证件类型 | **KYC 系统** | `kyc_status`, `id_type` |
| **注册来源 (Source)** | 是否来自高风险渠道/IP | **流量统计** | `registration_ip`, `utm_source` |

*   **判定标准示例**: 资金停留 < 10分钟 **或** 设备关联账号 > 3 **或** 仅交易赠金无充值。

## 3. 数据采集与处理架构建议

为了实时获取上述指标，建议搭建以下数据流：

1.  **实时流 (Real-time)**:
    *   **来源**: 撮合引擎、支付网关。
    *   **用途**: 实时更新 AUM、爆仓提醒、快进快出风控拦截。
    *   **技术**: Kafka + Flink。

2.  **离线批处理 (Batch)**:
    *   **来源**: 业务数据库 (MySQL/PostgreSQL)、埋点日志。
    *   **用途**: 计算 T+1 指标（如 30日活跃天数、最大回撤、用户层级更新）。
    *   **技术**: Data Warehouse (ClickHouse/Doris)。

3.  **标签服务 (Tag Service)**:
    *   将计算好的指标转化为标签（如 `Tag: Whale`, `Tag: High_Leverage`），通过 API 提供给运营后台和 CRM 系统使用。
