# 后台管理系统 - 任务配置与幸运大转盘 PRD (V2.1)

## 1. 文档概述
**核心变更**: 
1.  **任务系统升级**: 支持多种奖励组合发放（USDT + 积分 + 大转盘次数），不再局限于单一奖励类型。
2.  **国际化支持**: 任务配置全面支持多语言（名称、描述、Banner标题等）。
3.  **大转盘独立性**: 转盘作为独立资源池，增加样式自定义与精细化风控（必中白名单）。
4.  **数据联动**: 强化任务与转盘的数据关联统计。

**用户角色**: 运营管理员 (Operator), 财务管理员 (Finance), 超级管理员 (Admin)

## 第二部分：大转盘配置 (Lucky Wheel Configuration)

### 2.1 功能目标
管理独立的抽奖实例，配置奖品概率与风控规则。

### 2.2 页面布局与交互

#### 2.2.1 转盘列表页
*   **筛选区域**: `转盘ID`, `转盘名称`, `状态`。
*   **列表字段**:
    *   `ID`, `转盘名称`, `创建时间`
    *   `关联任务数`: [Tag + Popover]
        *   *交互*: 鼠标悬停显示具体关联的任务列表 (ID + 名称)，格式如 `212 交易赢大奖; 211 赚1000就好;`。
    *   `状态`: [Switch 开关] (开启/关闭)。
    *   `数据统计`: [查看报表] 按钮。
    *   **操作**: [配置], [名单配置], [中奖记录], [删除(需二次确认)]。
        *   **名单配置**: 点击弹出独立弹窗，管理“必中白名单”和“必不中黑名单”。
        *   **中奖记录**: 点击弹出独立弹窗，查看所有用户的中奖记录，并支持补发奖励。

#### 2.2.2 新建/编辑转盘 (Wizard Flow)
分步引导式配置 (Steps):

**Step 1: 基础设置 (Basic Settings)**
*   `转盘名称`: [输入框]
*   `转盘样式图`: [图片上传] (用于自定义转盘背景/皮肤)。
*   `备注`: [文本域]
*   `状态`: [Switch 开关]
*   **风控配置 (Risk Config)**:
    *   `单人总抽奖上限`: [单选: 无限 / 有限] (若选有限，输入最大次数)。
    *   `每日抽奖上限`: [单选: 无限 / 有限] (若选有限，输入最大次数)。
*   **编辑锁定逻辑**:
    *   当状态为 **“开启” (Active)** 时，基础设置（除状态外）和奖池配置将被**锁定（只读）**。仅允许修改“状态”。
    *   当状态为 **“关闭” (Inactive)** 时:
        *   **已存在的奖品**: “类型”和“名称/内容”不可修改（置灰），但可以修改“价值”、“库存”、“概率”。可以删除。
        *   **新添加的奖品**: 所有字段均可修改。

**Step 2: 奖池配置 (Prizes)**
*   **布局**: 右侧配置表格。
*   **奖品列表**: (8 ~ 20 个奖品)
    *   `类型`: [下拉: 实物 / 奖励金 / 优惠券 / 谢谢惠顾]
    *   `名称`: 
        *   若类型 = **优惠券**，显示 [下拉选择框]，选择已配置的优惠券。
        *   若类型 = **实物**，显示 [图片图标] (点击上传) + [输入框] (输入名称)。
        *   其他类型，显示 [输入框]。
    *   `价值(U)`: [数字输入] (奖品单价)。
    *   `库存(总/日)`: [数字输入] / [数字输入] (分别设置总库存和每日库存)。
    *   `概率(%)`: [数字输入] (支持3位小数)。
    *   `累计总价`: [自动计算] (价值 * 总库存)。
    *   `操作`: [删除]。
*   **校验**: 总概率必须严格等于 100%。

### 2.3 数据统计 (Statistics)
*   **弹窗展示**:
    *   **核心指标**: 总抽奖次数、已发放金额 (单位: U)、产出奖品数。
    *   **分活动/任务统计表**:
        *   `来源活动(任务)名称`
        *   `来源ID`
        *   `贡献抽奖次数`
        *   `消耗金额` (单位: U)

### 2.4 中奖历史记录 (Winning Records)
*   **弹窗展示**:
    *   **筛选区域**:
        *   `用户UID`: [输入框]
        *   `发放状态`: [下拉: 已发放 / 未发放]
    *   **记录列表**:
        *   `记录ID`
        *   `用户UID`
        *   `奖品名称`
        *   `中奖时间`
        *   `发放状态`
        *   **操作**: [补发奖励] (仅当状态为未发放时显示)
*   **补发奖励功能**:
    *   点击“补发奖励”按钮后，弹出确认对话框
    *   确认后，将该奖励的状态更新为已发放
    *   提供成功提示信息

## 3. 业务逻辑与约束
1.  **多语言存储**: 任务的多语言字段需以 JSON 格式存储或关联多语言表。
2.  **状态联动**: 
    *   转盘开启时，关联该转盘的任务才能正常发放次数。
    *   转盘编辑锁定机制是为了防止在用户抽奖过程中修改概率导致数据不一致。
3.  **优惠券关联**: 需确保优惠券系统接口可用，下拉列表仅展示有效的优惠券。
4.  **删除保护**: 已关联任务的转盘，或已产生数据的转盘，建议逻辑删除或禁止删除（前端已加二次确认）。
