# DeTrade App 版本更新功能解决方案

**文档版本**: v1.1  
**创建日期**: 2026-05-28  
**更新日期**: 2026-05-28  
**技术栈**: Flutter (iOS/Android)  
**目标**: 为 DeTrade 移动端 App (iOS/Android) 提供完整的版本更新产品方案，包括首版功能范围界定、后管配置设计、推送触发机制、用户体验流程等。

---

## 一、是否在第一个版本中加入更新功能？

### 结论：**强烈建议首版加入**

#### 理由分析：

| 维度 | 不加更新功能的风险 | 加入更新功能的收益 |
|------|-------------------|-------------------|
| **资金安全** | 出现安全漏洞时无法及时推送修复，可能导致用户资金风险 | 可快速推送更新，降低安全风险 |
| **用户体验** | 发现 bug 只能等 App Store/Google Play 审核（24-72小时） | 引导用户快速更新，减少负面体验 |
| **运营灵活** | 无法配合运营活动快速调整功能 | 可及时推送配合新活动的版本 |
| **合规要求** | 监管政策变化时需紧急更新，无法及时响应 | 可快速推送合规版本 |
| **竞品对比** | 竞品均具备完整更新机制，不加入即落后 | 保持与行业同等水平 |

#### 首版更新功能范围：

| 功能模块 | 是否加入首版 | 优先级 |
|---------|------------|--------|
| 版本检查接口（强制/可选更新） | **是** | P0 |
| 后管版本管理基础功能 | **是** | P0 |
| 客户端更新弹窗（强制/可选） | **是** | P0 |
| 灰度发布 | **否**，后续迭代 | P1 |
| 更新数据统计看板 | **否**，后续迭代 | P1 |
| 定时发布/预约发布 | **否**，后续迭代 | P2 |

## 二、更新功能整体架构

DeTrade App（Flutter 开发）需要建立一套完整的版本管理体系，核心包含两大模块：

```
┌─────────────────────────────────────────────────────────────┐
│                    DeTrade App 版本管理架构                  │
├─────────────────────────┬───────────────────────────────────┤
│   1. 后端版本配置系统    │   2. 客户端版本检查与更新引导      │
│   （后管系统）          │   （App 端）                       │
├─────────────────────────┼───────────────────────────────────┤
│ 功能：                   │ 功能：                             │
│ - 版本信息配置            │ - 启动时检查最新版本                │
│ - 更新类型设置            │ - 展示更新弹窗                      │
│ - 最低支持版本控制        │ - 引导用户跳转商店/下载             │
│ - 灰度发布控制            │ - 强制更新时阻断使用                │
│ - 地区/语言定向推送       │ - 可选更新允许稍后处理              │
│                          │                                   │
│ 目标用户：               │ 目标用户：                         │
│ - 运营人员               │ - App 终端用户                     │
│ - 产品人员               │                                   │
│ - 测试人员               │                                   │
└─────────────────────────┴───────────────────────────────────┘
```

### 核心业务流程

```
用户打开 App
    │
    ▼
App 启动，延迟 5 秒向服务端请求版本信息
    │
    ▼
服务端返回当前最新版本及更新策略
    │
    ▼
App 对比本地版本与服务端版本
    │
    ├── 无需更新 → 正常进入首页
    │
    ├── 可选更新 → 展示可选更新弹窗
    │              │
    │              ├── 用户点击「立即更新」→ 跳转应用商店
    │              │
    │              └── 用户点击「稍后更新」→ 关闭弹窗，正常使用
    │
    └── 强制更新 → 展示强制更新弹窗（不可关闭）
                   │
                   └── 用户点击「立即更新」→ 跳转应用商店
                                             │
                                             └── 更新完成后重新打开 App
```

## 三、版本检查 API 产品定义

### 3.1 接口概述

App 每次启动时（延迟 5 秒）调用此接口，获取当前最新版本信息，决定是否引导用户更新。

### 3.2 请求参数

| 参数名 | 类型 | 必填 | 说明 | 示例值 |
|--------|------|------|------|--------|
| `platform` | String | 是 | 设备平台 | `ios` / `android` |
| `app_version` | String | 是 | App 当前版本号（语义化版本） | `1.0.0` |
| `build_number` | String | 是 | App 当前构建号（递增整数） | `100` |
| `language` | String | 否 | 用户当前使用语言 | `zh-CN` / `en-US` |
| `country` | String | 否 | 用户所在国家/地区（用于区域定向推送） | `CN` / `US` |

### 3.3 返回数据结构

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "has_update": true,
    "update_type": "force",
    "latest_version": "1.1.0",
    "latest_build_number": "110",
    "min_supported_version": "1.0.0",
    "min_supported_build_number": "100",
    "title": "重要更新",
    "description": "本次更新包含重要的安全修复，请升级后继续使用。",
    "release_notes": "1. 修复了交易页面偶发崩溃问题\n2. 优化了行情列表加载速度\n3. 新增TON链充值支持",
    "download_url": {
      "ios": "https://apps.apple.com/app/id123456789",
      "android": "https://play.google.com/store/apps/details?id=com.detrade.app"
    },
    "android_apk_url": "https://cdn.detrade.com/app/detrade-v1.1.0.apk",
    "is_critical": true,
    "publish_time": "2026-05-28T10:00:00Z"
  }
}
```

### 3.4 关键字段产品含义

| 字段 | 产品含义 | 取值说明 |
|------|---------|---------|
| `has_update` | 是否有新版本可更新 | `true` = 有新版本，`false` = 已是最新 |
| `update_type` | 更新策略类型 | `force` = 强制更新（阻断使用）<br>`optional` = 可选更新（可稍后处理）<br>`silent` = 静默（不主动提示） |
| `min_supported_version` | 最低支持版本 | 低于此版本的 App 将被强制要求更新，否则无法继续使用核心功能 |
| `is_critical` | 是否紧急更新 | `true` 时即使用户关闭弹窗也会在下一次操作时再次弹出 |
| `android_apk_url` | Android 直链下载 | 用于中国大陆等无法访问 Google Play 的地区，提供 APK 直接下载 |

## 四、后管系统版本管理模块设计

### 4.1 功能菜单结构

```
后管系统 ─ 版本管理
├── 版本列表
│   ├── 查看所有版本推送记录
│   ├── 按平台/状态筛选
│   └── 查看推送详情与数据
│
├── 新建版本推送
│   ├── 基础信息配置
│   ├── 更新内容配置
│   ├── 推送策略配置
│   └── 下载链接配置
│
└── 更新统计（后续迭代）
    ├── 各版本更新成功率
    ├── 用户更新行为分析
    └── 更新漏斗数据
```

### 4.2 后管配置字段详细说明

创建/编辑版本推送时，需要配置以下字段：

#### A. 基础信息（必填）

| 字段名 | 类型 | 必填 | 说明 | 填写示例 |
|--------|------|------|------|---------|
| `platform` | 单选 | 是 | 目标平台 | iOS / Android / 双平台 |
| `version` | 文本 | 是 | 目标版本号（语义化版本） | `1.1.0` |
| `build_number` | 数字 | 是 | 目标构建号（与上传到商店的构建号一致） | `110` |

#### B. 更新策略（必填）

| 字段名 | 类型 | 必填 | 说明 | 选项 |
|--------|------|------|------|------|
| `update_type` | 单选 | 是 | 更新类型 | 强制更新 / 可选更新 / 静默 |
| `min_supported_version` | 文本 | 是 | 最低支持版本，低于此版本强制更新 | `1.0.0` |
| `is_critical` | 开关 | 是 | 是否紧急更新（开启后弹窗不可关闭） | 开 / 关 |

#### C. 更新内容（必填）

| 字段名 | 类型 | 必填 | 说明 | 填写示例 |
|--------|------|------|------|---------|
| `title` | 文本 | 是 | 弹窗标题，向用户展示 | `重要更新` / `发现新版本` |
| `description` | 多行文本 | 是 | 更新描述摘要，展示在弹窗正文 | `本次更新包含重要的安全修复，请升级后继续使用。` |
| `release_notes` | 多行文本 | 是 | 详细更新日志，支持换行 | `1. 修复了交易页面偶发崩溃问题\n2. 优化了行情列表加载速度\n3. 新增TON链充值支持` |

#### D. 下载链接（按平台条件必填）

| 字段名 | 类型 | 必填条件 | 说明 | 填写示例 |
|--------|------|---------|------|---------|
| `download_url_ios` | URL | 包含 iOS 时必填 | App Store 下载链接 | `https://apps.apple.com/app/id123456789` |
| `download_url_android` | URL | 包含 Android 时必填 | Google Play 下载链接 | `https://play.google.com/store/apps/details?id=com.detrade.app` |
| `android_apk_url` | URL | 可选 | Android APK 直链（中国大陆用户） | `https://cdn.detrade.com/app/detrade-v1.1.0.apk` |

#### E. 推送策略（可选）

| 字段名 | 类型 | 必填 | 说明 | 填写示例 |
|--------|------|------|------|---------|
| `rollout_percentage` | 数字 | 否 | 灰度推送比例（0-100） | `10` = 仅推送给 10% 的用户 |
| `target_country` | 多选 | 否 | 目标国家/地区，留空表示全球 | `中国`、`美国`、`韩国` |
| `target_language` | 多选 | 否 | 目标语言，留空表示所有语言 | `简体中文`、`English` |
| `start_time` | 日期时间 | 否 | 生效时间，留空表示立即生效 | `2026-05-28 10:00` |
| `end_time` | 日期时间 | 否 | 失效时间，留空表示永久有效 | `2026-06-28 10:00` |

#### F. 状态控制

| 字段名 | 类型 | 说明 | 选项 |
|--------|------|------|------|
| `status` | 状态机 | 推送状态 | 草稿 / 生效中 / 已暂停 / 已下架 |

### 4.3 更新类型说明

| 更新类型 | 产品行为 | 适用场景 | 用户是否可以跳过 |
|---------|---------|---------|----------------|
| **强制更新** | 弹出全屏遮罩弹窗，用户必须点击更新按钮跳转商店，无法使用 App 其他功能 | 安全漏洞修复、重大 bug、不兼容旧版本的 API 变更 | 否 |
| **可选更新** | 弹出弹窗展示更新内容，用户可选择「立即更新」或「稍后更新」 | 新功能上线、体验优化、非紧急问题修复 | 是 |
| **静默** | 不在客户端主动展示弹窗，仅在后管记录版本信息，供手动检查更新时对比 | 内部测试版本、小范围验证 | - |

## 六、推送触发机制

### 6.1 后管推送操作流程

```
运营/产品人员 登录 后管系统
    │
    ▼
进入「版本管理」页面，点击「新建版本推送」
    │
    ▼
填写版本信息（版本号、更新类型、更新内容、下载链接等）
    │
    ▼
配置推送策略（灰度比例、目标地区、生效时间等）
    │
    ▼
选择操作
    │
    ├── 保存为草稿 → 版本保存，不推送给用户
    │
    └── 立即发布 → 版本生效，开始向目标用户推送
           │
           ▼
    用户在下次打开 App 时接收到更新提示
```

### 6.2 灰度发布策略

**推荐三阶段灰度发布**：

| 阶段 | 推送比例 | 建议持续时长 | 观察指标 | 操作 |
|------|---------|-------------|---------|------|
| **第一阶段** | 10% | 2-4 小时 | 用户反馈、崩溃率 | 无明显负面反馈则进入下一阶段 |
| **第二阶段** | 50% | 4-8 小时 | 用户反馈、更新转化率 | 无明显负面反馈则全量 |
| **第三阶段** | 100% | 持续 | 常规监控 | - |

**灰度调整操作**：
- 在后管版本详情页可实时调整灰度比例
- 可随时暂停推送
- 全量推送后无法降低灰度比例（只能下架）

### 6.3 异常情况处理

| 异常场景 | 处理策略 | 后管操作 |
|---------|---------|---------|
| 新版本发现严重 bug | 立即暂停推送，下架该版本 | 后管点击「暂停」→「下架」 |
| 用户投诉激增 | 暂停推送，排查问题 | 后管点击「暂停」 |
| 商店审核未通过 | 下架版本，等审核通过后重新发布 | 后管点击「下架」 |
| 紧急安全漏洞需修复 | 发布强制更新版本，设最低支持版本 | 新建版本，选「强制更新」 |

### 6.4 客户端检查更新时机

| 时机 | 说明 | 频率限制 | 是否影响性能 |
|------|------|---------|-------------|
| App 冷启动 | 用户首次打开 App | 延迟 5 秒执行 | 低（延迟执行） |
| App 热启动 | 用户从后台切回前台 | 每小时最多 1 次 | 低 |
| 手动检查 | 用户在「设置-关于」点击「检查更新」 | 无限制 | 低 |
| 定时轮询 | 后台定时检查 | 每 6 小时 1 次 | 极低 |

**性能保护机制**：
- 版本检查请求超时时间 5 秒
- 请求失败不影响 App 正常使用，下次启动再检查
- 检查结果可本地缓存 6 小时，避免频繁请求

## 九、App Store / Google Play 合规说明

### 9.1 Apple App Store 合规要点

| 要求 | 说明 | DeTrade 合规方式 |
|------|------|-----------------|
| 允许下载解释执行代码 | Apple 允许下载 JS 代码 | 本方案不涉及代码热更新，仅引导用户通过商店更新，完全合规 |
| 不改变应用主要目的 | 更新不能改变 App 核心功能 | 版本引导不改变 App 功能 |
| 不构建代码分发平台 | App 不能作为应用商店 | 不涉及 |

### 9.2 Google Play 合规要点

| 要求 | 说明 | DeTrade 合规方式 |
|------|------|-----------------|
| 不下载可执行代码 | 禁止从 Google Play 以外下载可执行代码 | 本方案仅引导用户通过 Google Play 或官方 APK 更新，合规 |
| APK 直链需注意 | 提供 APK 直链时需确保安全 | APK 使用 HTTPS + 签名校验 |

## 十一、总结与产品建议

### 首版必做功能清单：

1. **版本检查 API** - 支持强制/可选/静默三种更新策略
2. **最低版本控制** - 低于最低版本的 App 将被强制要求更新
3. **后管版本管理页面** - 支持版本配置、发布、暂停、下架
4. **客户端更新弹窗** - 强制更新（不可关闭）和可选更新（可关闭）两种模式
5. **手动检查更新入口** - 在「设置-关于」页面提供手动检查入口
6. **灰度比例配置** - 支持 10% → 50% → 100% 分阶段推送

### 后续迭代功能清单：

1. **定时发布/预约发布** - 预设版本生效时间
2. **地区/语言定向推送** - 按国家/地区、语言推送不同版本
3. **更新数据统计看板** - 更新成功率、用户行为分析、更新漏斗
4. **自动暂停机制** - 异常指标自动暂停推送
5. **多语言更新文案** - 按用户语言展示不同更新描述
6. **更新历史记录** - 记录每次版本变更操作
