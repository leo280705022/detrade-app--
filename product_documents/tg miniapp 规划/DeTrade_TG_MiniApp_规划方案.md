# DeTrade TG Mini App All-In 规划方案

## 1. 战略定位与核心目标

### 1.1 背景
DeTrade 当前以 H5 + 规划中的原生 App 为主阵地。TG Mini App 赛道已被 Storm Trade、Blum 等竞品验证为加密交易领域的**流量洼地**，TG 9 亿月活用户中蕴含大量未触达的 Crypto 交易人群。

### 1.2 战略目标
**All-In TG Mini App**，不是简单做一个 TG 版本，而是将 TG 生态作为**第一增长引擎**，构建完整的 "引流 → 转化 → 留存 → 裂变" 闭环。

### 1.3 核心原则（来自老板架构图）
| 原则 | 含义 | 对应架构层 |
|:---|:---|:---|
| **轻量化** | 打开快，最少 JS/CSS，3 秒进局 | ⑤ 收口层 |
| **防封冗余** | 炮灰马甲 + 热切换，单点被封不波及全局 | ⑧ 归因与防封中枢 |
| **信任前置** | 合规牌照背书第一屏喊出 | ③ 信任锚点层 |
| **无摩擦转化** | bonus + 无 KYC，一跳进局 | ② 钩子层 |
| **全链归因** | deep link 编码每渠道 reg→FTD | ⑧ 归因中枢 |

## 2. 架构拆解：九层漏斗

基于老板的 SVG 架构图，将整体交互架构拆解为 **9 个层次、3 条主线**：

```
┌─────────────────────────────────────────────────────────┐
│                    ⑧ 归因与防封中枢 (贯穿全链)              │
├─────────────────────────────────────────────────────────┤
│  ① 投放分发层  →  ② 钩子层  →  ③ 信任锚点  →  ④ 多语言频道  │
│       ↓               ↓            ↓             ↓       │
│  ⑤ 收口层(Main Bot)  →  ⑥ 转化漏斗  →  ⑦ 客服与裂变       │
├─────────────────────────────────────────────────────────┤
│                    ⑨ 融合心法 (各取所长)                    │
└─────────────────────────────────────────────────────────┘
```

### 三条主线
- **红线（永旺打法）**: 投放马甲号 → 认证频道备份 → 防封冗余 → 热切换
- **蓝线（TonPlay 打法）**: 官方社媒矩阵 → Bonus 火力 → 合规背书 → 多语言矩阵
- **绿线（收口转化）**: 主 Bot → 注册 → 首充 → 留存 → 裂变回流

## 3. 各层详细规划

### 3.1 投放与分发层 —— 流量入口矩阵

**现状**: DeTrade 已有联盟伙伴 V2 体系、KOL 专项计划、分享裂变功能。

**TG Mini App 规划**:

| 渠道类型 | 具体方案 | 优先级 | 技术要点 |
|:---|:---|:---|:---|
| **马甲号矩阵** | 批量注册 TG 号，中性话术（"玩赚 Crypto"），不发直链 | P0 | 号池管理后台，话术模板库 |
| **官方社媒** | X/IG/YouTube 内容 → TG 频道导流 | P1 | 统一短链 + UTM 参数 |
| **KOL 联盟** | 复用现有 KOL Star Program，提供专属 deep link | P0 | 复用联盟 V2 返佣体系 |
| **玩家裂变** | 推荐 deep link + 红包裂变 + 晒单回流 | P0 | 见 3.7 |

**关键设计**:
- 马甲号**不直接暴露主 Bot**，通过中间跳转层（频道/群）缓冲
- 每个投放渠道独立 deep link 编码，可追踪到人

### 3.2 钩子层 —— Bonus 开门炮

**现状**: DeTrade 已有完整的奖励金体系（体验金、抵扣金、积分、现金红包），以及新手任务、签到系统。

**TG Mini App 规划**:

```
用户点击链接/扫描二维码
        ↓
   Landing Page（极简，<50KB）
        ↓
  "领取 10 USDT 体验金" ← 核心钩子
        ↓
  无需 KYC，即点即玩
        ↓
  进入主 Bot（3 秒内完成）
```

| 钩子类型 | 详情 | 风控措施 |
|:---|:---|:---|
| **无存款奖** | 注册即送 5-10 USDT 体验金 | 设备指纹 + IP 检测 + T+N 提现 |
| **高额首充** | 首充 ≥ 50 USDT，送 100% 体验金 | 交易量解锁提现门槛 |
| **每日返水** | 日交易返水，TG 内一键领取 | 复用现有返水系统 |
| **Gas-Free** | TON 链出入金免 Gas（限时） | 额度上限控制 |

**技术注意**:
- Landing Page 必须极致轻量（纯 HTML + 内联 CSS，无框架）
- 红包功能通过 TG Bot API 的 `sendInvoice` 或自定义实现

### 3.3 信任锚点层 —— 双背书

**TG Mini App 规划**:

| 背书维度 | 实现方式 | 技术方案 |
|:---|:---|:---|
| **认证频道** | TG 官方蓝V认证频道，置顶永久导流 | TG Channel + 置顶消息 |
| **马甲备用** | 3+ 备用频道，主频道被封自动切换 | 后端配置热更新，Bot 指令切换 |
| **合规牌照** | 频道描述 + 首屏展示 Brazil 双牌照 | 频道 Bio + Mini App 首页 |
| **Provably Fair** | 交易结果可验证哈希 | 后端提供验证接口 |
| **Trustpilot** | 嵌入好评截图 + 实时评分 | 静态图 + API 拉取 |

### 3.5 收口层 —— 主 Bot · DeTrade Mini App

这是整个架构的**心脏**，也是 TG 用户体验的核心载体。

**设计原则**:
- ⚡ **极致轻量**: 首屏 HTML+CSS+JS < 100KB（不含图片）
- ⚡ **3 秒进局**: 从点击到可交易 < 3 秒
- ⚡ **Chat 内闭环**: 注册、充值、交易、提现全在 Bot 内完成

**功能模块规划**:

```
┌──────────────────────────────────────┐
│          DeTrade Main Bot            │
├──────────────────────────────────────┤
│  /start   → 欢迎页 + 领体验金         │
│  /trade   → 极简交易面板              │
│  /wallet  → 资产总览 + 充提           │
│  /earn    → 任务中心 + 邀请返佣        │
│  /help    → 客服分流                  │
│  /games   → 游戏大厅（PVP/大转盘等）    │
└──────────────────────────────────────┘
```

**MVP 阶段（P0）功能**:
1. **注册/登录**: TG 一键授权登录（通过 `tgWebApp.initData`），无需邮箱/手机
2. **入金**: 支持 TON 链快捷充值 + USDT 充值
3. **极简交易**: UpDown 二元期权（30s/60s/120s/5m），核心交易界面
4. **资产看板**: 余额、盈亏简表
5. **体验金领取**: 自动触发新手奖励

**第二阶段（P1）功能**:
6. **合约交易**: 简化版永续合约（杠杆 1x-100x）
7. **邀请返佣**: 生成个人 deep link，查看返佣数据
8. **任务中心**: 签到、新手任务、进阶任务
9. **红包功能**: 群红包、个人红包

**第三阶段（P2）功能**:
10. **PVP 对战**: 多人涨跌对战房间
11. **大转盘**: 积分抽奖
12. **奖池瓜分**: 平台利润分红

### 3.6 转化漏斗 —— Bot 内闭环

```
访问 Landing Page
      ↓  ~100%
TG 一键授权注册
      ↓  ~40-50%（提升自 0.38%）
领取体验金 + 首次交易
      ↓  ~20-30%
首次充值（FTD）
      ↓  ~10-15%
持续交易 / 复购
```

**关键优化点**:
- 取消 KYC 注册门槛（TG 账号即身份）
- 体验金引导首次交易（"这笔亏损我们包赔"）
- 小额首充（$10 起）降低心理门槛
- 首充后立即推送高收益交易机会

### 3.7 客服与裂变 —— 独立分线

**客服 Bot（独立于主 Bot）**:
- 与主 Bot 分开，避免污染用户行为数据
- 支持中/英/葡/西 多语
- 初始阶段人工客服 + FAQ 自动回复
- 后续接入 AI Agent

**裂变机制**:
| 裂变方式 | 触发场景 | 激励机制 |
|:---|:---|:---|
| **红包裂变** | 用户盈利后一键发红包到群 | 红包领取者自动注册 |
| **晒单裂变** | 盈利 > 50% 自动生成战绩海报 | 晒单得积分/抵扣金 |
| **推荐裂变** | 个人 deep link 邀请 | 返佣（复用联盟 V2） |
| **复活裂变** | 爆仓后弹窗"邀请 1 人复活" | 亏损抵扣券 |
| **拼团裂变** | 3 人拼团免手续费 | 私域转发动力 |

**技术要点**:
- 红利海报: 后端生成图片（Puppeteer/Sharp），Bot 发送
- 红包: 利用 TG Bot 消息按钮 + 后端红包资金池
- Deep link: `https://t.me/DeTradeBot?start=ref{userId}`

### 3.8 归因与防封中枢 —— 贯穿全链

**全链归因体系**:

```
投放渠道 ID (channel_id)
    → 马甲号 ID (sock_id)
        → 中间频道/群 ID (buffer_id)
            → 用户 deep link (ref_code)
                → 注册 (reg)
                    → 首次交易 (first_trade)
                        → 首充 (FTD)
                            → 留存/复购 (retention)
```

**归因数据表设计**:
```sql
TABLE tg_attribution (
    id BIGINT,
    user_id BIGINT,
    channel_id VARCHAR(32),      -- 投放渠道
    sock_id VARCHAR(32),         -- 马甲号
    buffer_type VARCHAR(16),     -- 频道/群/直连
    buffer_id VARCHAR(32),       -- 中间载体 ID
    ref_code VARCHAR(64),        -- 邀请码
    land_time TIMESTAMP,         -- 落地时间
    reg_time TIMESTAMP,          -- 注册时间
    first_trade_time TIMESTAMP,  -- 首笔交易时间
    ftd_time TIMESTAMP,          -- 首充时间
    ftd_amount DECIMAL(20,2),    -- 首充金额
    status VARCHAR(16)           -- active/churned/banned
);
```

**三层冗余防封**:
```
Layer 1: 炮灰马甲号（投放前线，被封即弃）
    ↓ 被封时自动切换
Layer 2: 备用频道/群（中间缓冲，多个热备）
    ↓ 主频道被封时切换
Layer 3: 合规主 Bot（藏于第二跳，不暴露前线）
    ↓ 多个 Bot 互为备份
```

**技术实现**:
- 号池管理系统: 监控每个号/频道/Bot 状态
- 自动切换: 检测到封禁 → 自动切换备用 → 更新 deep link 指向
- 分市场隔离: Brazil 被封不影响 Mexico

### 3.9 融合心法 —— 各取所长

| 打法 | 贡献 | 应用层 |
|:---|:---|:---|
| **永旺打法** | 投放第一线用可弃马甲 + 中性话术 + 热切换防封 | ①②⑧ |
| **TonPlay 打法** | Bonus 火力开门 + 合规牌照背书 + 多语言矩阵 + 客服分线 | ②③④⑦ |
| **收口原则** | 所有渠道收到唯一主 Bot，永不让主体直吃投放流量 | ⑤ |
| **信任原则** | 合规背书在前屏喊出 | ③ |
| **效率原则** | Bonus + 无 KYC 把打开压到一跳进局 | ②⑤⑥ |
| **归因原则** | Deep link 全链编码，每渠道质量可查 | ⑧ |

## 4. 技术实现路径

### 4.1 TG Mini App 技术选型

由于核心要求是**轻量、打开快、最少 JS/CSS**，技术选型必须极度克制：

| 技术选型 | 方案 | 理由 |
|:---|:---|:---|
| **前端框架** | 原生 HTML/CSS/JS + TG WebApp SDK | 最小体积，无框架开销 |
| **CSS 方案** | 内联 `<style>` + CSS Variables | 减少请求，利用 TG 主题变量 |
| **JS 体积** | < 50KB (gzip) | 手动编写，不用 npm 包 |
| **后端 API** | 复用现有 DeTrade 后端 API | 新增 TG 专用轻量接口 |
| **Bot 框架** | Node.js + Grammy/Telegraf | 成熟稳定 |
| **图片生成** | 后端 Sharp/Canvas | 海报、战绩图 |

### 4.2 TG WebApp SDK 集成要点

```javascript
// TG Mini App 核心能力利用
const tg = window.Telegram.WebApp;

// 1. 一键授权登录 - 后端验证 initData
const initData = tg.initData;
// 发送到后端验证 hash，提取用户信息

// 2. 主题适配
tg.themeParams.bg_color     // 背景色
tg.themeParams.text_color   // 文字色
tg.themeParams.button_color // 按钮色

// 3. 主按钮
tg.MainButton.setText('开始交易').show().onClick(openTrade);

// 4. 触觉反馈
tg.HapticFeedback.impactOccurred('medium');

// 5. 返回按钮
tg.BackButton.show().onClick(goBack);
```

### 4.3 性能目标

| 指标 | 目标值 | 测量方式 |
|:---|:---|:---|
| 首屏加载 | < 1.5s (3G 网络) | Lighthouse / WebPageTest |
| HTML 大小 | < 30KB | 文件大小 |
| CSS 大小 | < 15KB | 文件大小 |
| JS 大小 | < 50KB (gzip) | 文件大小 |
| 总资源 | < 150KB (首屏) | DevTools Network |
| 可交互时间 (TTI) | < 3s | Lighthouse |
| Landing → 交易 | < 3 步 | 用户路径 |

## 5. 多 Bot 架构设计

### 5.1 Bot 矩阵

```
┌─────────────────────────────────────────────────┐
│                  Bot 矩阵                         │
├─────────────────────────────────────────────────┤
│  Main Bot        → 交易、资产、游戏（核心）         │
│  CS Bot          → 客服、FAQ、工单                 │
│  Notification Bot → 行情预警、爆仓通知、活动推送      │
│  Marketing Bot   → 活动落地页、红包分发              │
│  Backup Bot 1..N → 主 Bot 热备，封禁切换            │
└─────────────────────────────────────────────────┘
```

### 5.2 Bot 间通信

- 主 Bot ↔ 客服 Bot: 用户点击"联系客服" → 跳转 CS Bot
- 主 Bot → 通知 Bot: 用户交易成功后，通知 Bot 推送消息
- 营销 Bot → 主 Bot: 活动落地页点击 → 打开主 Bot
- 所有 Bot 共享同一后端用户数据库

### 6.1 红包类型

| 类型 | 触发方式 | 分发机制 | 风控 |
|:---|:---|:---|:---|
| **群红包** | 用户在群内发送 | 拼手气/等额，设定数量和总金额 | 单日上限 |

### 6.2 技术实现

```
发红包流程:
用户触发 → 后端扣款 → 生成红包记录 → Bot 发送消息(内联按钮)
    ↓
领取流程:
用户点击 → 后端验证 → 检查是否已领取 → 入账 → 更新红包状态
```
