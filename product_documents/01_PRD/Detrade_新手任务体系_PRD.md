# Detrade 新手任务体系 PRD (V1.0)

## 1. 需求分析与风控评估 (Analysis & Risk Assessment)

### 1.1 核心目标
本需求旨在通过**"Demo 引导 -> 注册激励 -> 任务教学 -> 真金转化"**的闭环路径，解决新用户对二元期权/合约产品"不敢玩、不会玩"的痛点。核心在于利用**体验金 (Trial Fund)** 降低试错成本，利用**即时反馈 (Instant Feedback)** 建立心流。

### 1.2 业务流程拆解
1.  **游客 Demo 期**: 用户未注册时，在 Demo 账户交易产生特定行为（盈利/亏损/连胜）时，触发强引导弹窗，用 "10U 真金" 诱导注册。
2.  **注册认知期**: 注册成功即送 "2U 交易券 x5"（合计 10U），引导用户去交易。
3.  **任务教学期**:
    *   浏览页面/观看视频 -> 送 5U 交易券。
    *   完成首笔交易 -> 无论盈亏均给正向反馈（盈利提现/亏损送保险）。
4.  **首充转化期**: 完成首笔自有资金交易 -> 送 "新手毕业大礼包" (奖励金+保险券+抵扣券)。

### 1.3 深度风控评估 (Risk Assessment) - *CEX 产品经理视角*

该方案最大的风险在于**"注册即送 10U 真金体验券"**。如果不加限制，羊毛党会批量注册，利用这 10U 进行对敲或概率博弈，套取平台资金。

| 风险点 | 攻击方式 | **防御机制 (Mitigation Strategy)** |
| :--- | :--- | :--- |
| **批量注册 (Sybil Attack)** | 使用脚本批量生成邮箱/钱包地址注册，领取 10U 券。 | 1. **设备指纹**: 同一 Device ID / IP 仅限领取 1 次。<br>2. **KYC 前置/后置**: 建议**提现前必须 KYC Lv.1**。虽然注册不强求，但提现必须卡住。<br>3. **同源检测**: 提现地址若关联到同一交易所充值地址，直接封禁。 |
| **对敲套利 (Hedging)** | 账号A 开多，账号B 开空。必有一方盈利，套现离场。 | 1. **券属性限制**: 体验金**不可提现**，仅盈利部分可提。<br>2. **盈利提取门槛**: 体验金盈利部分需完成 **10倍 交易量** (Turnover) 才能解锁提现。<br>3. **持仓限制**: 体验金订单**禁止双向持仓**；限制最高杠杆 (e.g. 20x)。 |
| **无风险博弈** | 用户只用送的券玩，赢了提走，输了走人，平台纯亏。 | **入金激活**: 即使盈利了解锁了，提现前必须**至少充值一笔** (e.g. 10U) 并完成一次真实交易，验证这是个真人且有付费能力。 |
| **视频任务作弊** | 直接拖动进度条或脚本刷接口完成任务。 | 1. **前端埋点**: 监听 `video_play` 事件，禁止拖动进度条，必须播放满 30s。<br>2. **后端校验**: 任务完成请求需带上加密的时间戳签名 (Signature)。 |

## 3. 交互原型描述 (UI/UX Prototype)

### 3.1 首页/交易页 (游客态)
*   **浮层**: 右下角悬浮 "新手挑战: 赢 10U"。
*   **结算弹窗**: Demo 交易结算后，覆盖半屏 Modal。
    *   *标题*: "注册领取 $10"
    *   *主图*: 金币撒落动效。
    *   *按钮*: "立即领取" (高亮) / "继续模拟" (弱化)。

### 3.2 任务中心 (Task Center)
*   **入口**: 首页金刚区 "新手任务"。
*   **布局**: 进度条式布局 (Step 1 -> Step 2 -> Step 3)。
    *   *Step 1 (已完成)*: 注册账号 (打钩)。
    *   *Step 2 (进行中)*: 观看视频 (0/30s)。按钮 "去观看"。
    *   *Step 3 (锁定)*: 完成首单。
*   **反馈**: 每完成一步，触发 "金币飞入钱包" 动画。

## 4. 后台配置需求 (Admin Requirements)

1.  **任务配置**:
    *   开关任务、调整奖励金额、调整视频 URL。
2.  **风控配置**:
    *   `Global_Max_Trial_Daily`: 每日全平台体验金发放上限 (e.g. 10,000 U)。
    *   `Device_Limit`: 单设备限制领取次数。
    *   `Withdraw_Unlock_Volume`: 体验金盈利提现所需交易倍数 (e.g. 10x)。
3.  **数据报表**:
    *   新手任务转化漏斗 (注册 -> 观看 -> 首单 -> 首充)。
    *   体验金核销率与 ROI (发放金额 vs 带来的充值金额)。

---

## 5. 总结
本 PRD 将运营需求转化为了一套**"强引导、低门槛、重风控"**的产品方案。
*   **体验**: 通过 Demo 钩子和分步奖励，让用户"爽"起来。
*   **风控**: 通过**体验金不可提、盈利需解锁、提现需首充**三道防线，锁死羊毛党的套利空间。
