# DeTrade 联盟伙伴与邀请计划 V2 升级方案 (Affiliate & Referral System V2)

## 1. V1 版本回顾与痛点分析 (As-Is Analysis)

基于现有 V1 版本文档分析，当前体系主要存在以下局限性，限制了代理商规模化扩张和平台的资金效率：

| 维度 | V1 现状 | 痛点/风险 |
| :--- | :--- | :--- |
| **代理层级** | 简单的两级结构 (一级 -> 二级 -> 用户)。 | 结构僵化，无法支持大型 KOL 团队（通常需要 3 层以上利益分配，如：大区 -> 队长 -> 组员）。 |
| **结算周期** | **周结** (每周一统计，周二发)。 | 反馈太慢。代理商无法即时看到推广效果，降低了推单积极性。 |
| **负值处理** | 提到“Claim 负数问题”，但未明确规则。 | **致命风险**。若采用“客损模式”，用户盈利导致代理佣金为负时，若不累积到下期，代理商会利用周期套利（亏损期拿钱，盈利期换号）。 |
| **管理后台** | 功能简陋，仅基础数据。 | 缺乏“下放比例”的自主权；一级代理无法有效激励二级代理；缺乏用户行为画像。 |
| **风控体系** | 依赖人工复核。 | 容易被“手续费刷单”攻击（代理自己开小号对敲刷手续费返佣）。 |

---

## 2. V2 核心升级目标 (To-Be Objectives)

V2 版本的核心理念是 **"SAAS 化"** 和 **"自动化"**。我们要让一级代理商感觉自己是在“开交易所”，而不仅仅是“拉人头”。

1.  **代理体系 SAAS 化**: 提供独立 Web 管理后台，支持多层级、自定义分润。
2.  **结算机制实时化**: 从“周结”升级为 **"实时预估，日结/周结可选"**，提升感知。
3.  **风控与负值闭环**: 建立完善的“盈亏结转 (Carry Forward)”机制和反刷单系统。
4.  **混合分润模型**: 支持单条代理线同时存在“手续费模式”和“客损模式”的混合配置。

---

## 3. V2 详细功能设计 (Functional Specification)

### 3.1 代理层级与权益重构 (Tiered Structure)

将原有的“一级/二级”概念升级为 **"双轨动态层级体系"**。

*   **Tier 1: Master Agent (一级代理/顶级合伙人)**:
    *   **定义**: 拥有独立招商能力的团队长或 KOL。
    *   **等级划分**: 细分为 **Lv.1 - Lv.3** 三个子等级。
    *   **权限**: 拥有独立 Web 后台，可**无限开通**下级代理线，可设置下级分润比例。
    *   **分润权**: 平台给 Master 最高 70%-80% 总包。
    *   **数据权**: 可查看整条线的聚合数据（注册、入金、交易量、净盈亏）。

*   **Tier 2: Sub Agent (二级代理/普通代理)**:
    *   **定义**: 刚起步的推广者或社区群主。
    *   **等级划分**: 细分为 **Lv.1 - Lv.5** 五个子等级。
    *   **权限**: 仅能邀请普通用户 (User)，**不可**再发展下级代理（直到晋升为 Tier 1）。
    *   **后台**: 嵌入在 App/Web 个人中心的高级页面。

*   **User (普通用户)**:
    *   **权益**: 仅享受“邀请好友”的基础奖励，不参与永久分润。

### 3.2 动态等级与晋升机制 (Leveling & Promotion)

新增 **"下线活跃度"** 作为核心考核指标。

#### A. 等级权益表 (Level Table)

| 身份 | 等级 | 达成条件 (月度考核，满足其一即可) | 权益 (基础佣金比例) | 结算周期 |
| :--- | :--- | :--- | :--- | :--- |
| **Tier 2** | **Lv.1** | 注册即默认 | 15% (手续费) / 10% (客损) | 月结 (T+30) |
| (Sub) | **Lv.2** | 有效新增 > 3人 OR 活跃用户 > 10人 & 交易额 > 10k | 20% / 15% | 半月结 (T+15) |
| | **Lv.3** | 有效新增 > 10人 OR 活跃用户 > 30人 & 交易额 > 50k | 25% / 20% | 周结 (T+7) |
| | **Lv.4** | 有效新增 > 30人 OR 活跃用户 > 100人 & 交易额 > 200k | 30% / 25% | 周结 (T+7) |
| | **Lv.5** | 有效新增 > 50人 OR 活跃用户 > 200人 & 交易额 > 500k | 35% / 30% | 周结 (T+3) |
| | | | | |
| **Tier 1** | **Lv.1** | 直推 Sub Agent > 3个 & 团队总额 > 2M | 50% / 40% | 日结 (T+1) |
| (Master) | **Lv.2** | 直推 Sub Agent > 10个 & 团队总额 > 10M | 60% / 50% | 日结 (T+1) |
| | **Lv.3** | 直推 Sub Agent > 30个 & 团队总额 > 50M | 70% / 60% | 日结 (T+1) |

*注：不同等级结算周期不同，等级越高，资金回笼越快，以此激励代理商升级。*

#### B. 晋升逻辑与利益保护 (Promotion & Override Protection)

**晋升条件**: 当 Tier 2 达到 **Lv.5** 且维持一个月，可申请成为 Tier 1。

**利益保护示例 (Override Mechanism)**:
*   **场景**: 
    *   **A** 是 Tier 1 (Master)，享受 60% 佣金。
    *   **B** 是 A 下面的 Tier 2 (Sub)，享受 35% 佣金。此时 A 赚取差价 25%。
    *   **B** 业绩爆发，申请升级为 Tier 1 (Master)，佣金升至 50%。
*   **问题**: B 升级后与 A 平级，A 失去了 B 的差价，通常会导致 A 打压 B。
*   **解决方案**: 
    *   B 在行政架构上脱离 A，成为独立 Master。
    *   平台给予 A **"培育奖励 (Override)"**: 永久享受 B 团队总业绩的 **3% - 5%** 额外分红。
    *   **计算**: 假设 B 团队月佣金 100,000 U。
        *   升级前: A 赚差价 (60%-35%) = 25,000 U。
        *   升级后: A 赚培育奖 (5%) = 5,000 U。
        *   *虽然变少了，但 B 独立后会裂变出 10 倍的业绩，A 的 5% 总量可能高于原来的 25% 差价，且无需管理 B 的琐事。*

### 3.3 KOL 专项邀请计划 (KOL Star Program)

KOL 与普通代理不同，他们自带流量但缺乏精细化运营能力。

*   **准入机制**: 需人工审核，要求社交媒体粉丝 > 5,000 (YouTube/Twitter/Telegram)。
*   **激励模型**: 
    *   **基础返佣**: 享受 **手续费返佣** 或 **净亏损返佣 (客损)**，具体比例根据 KOL 影响力人工配置（参考 Tier 1 级别）。
    *   **粉丝福利**: KOL 专属邀请链接，粉丝注册享 **手续费 9 折** (Kickback)。
    *   **其他激励**: 暂无（签约金、保底机制等暂不实施，后续版本迭代考虑）。
*   **内容合作**: 平台提供“PVP 对战资金”给 KOL 做直播抽奖，而非直接给 KOL 现金。

### 3.4 独立代理后台需求 (Agent SAAS Specs)

该系统独立于 DeTrade 主站 (e.g., `agent.detrade.com`)。

#### A. 功能模块定义

1.  **首页/仪表盘 (Dashboard)**
    *   **关键指标**: 昨日佣金、本月累计佣金、下级总人数、活跃交易人数。
    *   **图表**: 注册转化漏斗 (点击->注册->入金->交易)。
    *   **待办**: 待审核的提现、待处理的下级申请。

2.  **成员管理 (Member Management)**
    *   **下级代理列表**: 查看名下 Sub Agent 业绩，调整其返佣比例（0%-40%）。
    *   **直推用户列表**: 用户 UID、注册时间、KYC 状态、**最后交易时间** (用于唤醒)。
    *   **转移划转**: 支持将某个用户划转给名下的 Sub Agent (需审核)。

3.  **财务中心 (Finance Center)**
    *   **佣金钱包**: 独立于交易账户。支持 划转至主账户 / 提现至链上地址。
    *   **报表下载**: 导出 Excel (日期/来源/金额/类型)，支持对账。
    *   **结算记录**: 查看每期结算单 (Settlement Note)，包含 负值结转详情。

4.  **营销工具箱 (Marketing Kit)**
    *   **多渠道链接**: 创建不同链接用于追踪来源 (e.g., "Link_Twitter", "Link_Youtube")。
    *   **Banner 生成器**: 自动合成带有邀请码的推广海报。
    *   **APP 唤醒**: 生成 Deep Link，用户点击直接拉起 APP 注册页。

#### B. 系统架构要求

*   **数据隔离**: 代理后台只读 `slave` 库的聚合数据，严禁直接查询核心交易库，防止拖垮主站。
*   **延迟敏感度**: 
    *   注册数据: 实时 (< 5s)。
    *   交易量/佣金预估: 准实时 (10-30 min 更新)。
    *   结算数据: 每日/每周 定时快照。

### 3.5 核心返佣模型优化 (Commission Models)

#### A. 净亏损模式 (Net Loss / CPA) - *高风险高收益*
适用于二元期权、高倍合约等博弈类产品。
*   **公式**: `返佣 = (下级总亏损 - 下级总盈利 - 资金成本 - 平台基础费率) * 返佣比例`
*   **V2 改进 - 盈亏结转 (High Water Mark)**:
    *   若本个结算周期（如本周）计算结果为 **负数**（即用户赚了，代理亏了），该负值 **必须滚入下一周期**。

#### B. 手续费模式 (Trading Fee / CPS) - *稳健收益*
适用于合约交易、跟单交易。
*   **公式**: `返佣 = 下级产生的总手续费 * 返佣比例`
*   **V2 改进 - 真实交易判定**:
    *   排除 **"短时间高频对敲"** 产生的垃圾手续费（防止刷单）。

---

## 4. 总结
V2 版本通过 **"双轨层级 + 身份跃迁 + KOL 专项 + 独立后台"** 四大模块，构建了一个既能满足蚂蚁雄兵（Sub Agent），又能承载大象起舞（Master Agent/KOL）的立体化增长网络。
