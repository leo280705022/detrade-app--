## 二、项目背景与目标

### 2.1 项目背景

DeTrade 移动端 App（基于 Flutter 开发，支持 iOS/Android 双平台）即将发布第一个版本。作为加密货币交易所应用，涉及用户资金安全和交易核心功能，需要具备完善的版本管理能力，以确保：

1. **安全风险快速响应** - 出现安全漏洞时能及时引导用户更新
2. **用户体验保障** - 发现 bug 时能快速推送修复版本
3. **运营灵活** - 配合运营活动及时发布新版本
4. **合规要求** - 监管政策变化时需紧急更新

### 2.2 项目目标

| 目标 | 说明 | 衡量指标 |
|------|------|---------|
| 建立版本管理体系 | 后管可配置版本信息、推送策略 | 后管功能可用性 100% |
| 支持多种更新策略 | 强制更新、可选更新、静默 | 三种策略均可正常触发 |
| 保障用户更新体验 | 弹窗交互友好，更新路径清晰 | 更新转化率 > 70% |
| 支持灰度发布 | 分阶段推送，降低风险 | 支持 10% → 50% → 100% 灰度 |

### 2.3 用户角色

| 角色 | 说明 | 使用场景 |
|------|------|---------|
| 运营人员 | 配置版本推送内容 | 发布新版本、配置更新文案 |
| 产品人员 | 制定版本更新策略 | 设置最低支持版本、灰度比例 |
| App 终端用户 | 接收更新提示并执行更新 | 打开 App 时看到更新弹窗 |

```

    │
    ▼

    │
    ▼
服务端返回最新版本及更新策略
    │
    ▼
App 对比本地版本与服务端版本
    │
    ├──────────────┬──────────────┐
    ▼              ▼              ▼
 无需更新       可选更新        强制更新
    │              │              │
    ▼              ▼              ▼
正常进入首页  展示可选更新弹窗  展示强制更新弹窗
                │              （不可关闭）
        ┌───────┴───────┐        │
        ▼               ▼        ▼
   点击「稍后更新」  点击「立即更新」 点击「立即更新」
        │               │           │
        ▼               ▼           ▼
    关闭弹窗，      跳转应用商店   跳转应用商店
    正常使用        或下载 APK    或下载 APK
```

```

    │
```

## 五、功能详细设计

### 5.1 版本检查 API

#### 5.1.1 接口概述

App 每次启动时（延迟 5 秒）调用此接口，获取当前最新版本信息，决定是否引导用户更新。

#### 5.1.2 请求参数

| 参数名 | 类型 | 必填 | 说明 | 示例值 |
|--------|------|------|------|--------|
| `platform` | String | 是 | 设备平台 | `ios` / `android` |
| `app_version` | String | 是 | App 当前版本号（语义化版本） | `1.0.0` |
| `build_number` | String | 是 | App 当前构建号（递增整数） | `100` |
| `language` | String | 否 | 用户当前使用语言 | `zh-CN` / `en-US` |
| `country` | String | 否 | 用户所在国家/地区（用于区域定向推送） | `CN` / `US` |

#### 5.1.3 返回数据结构

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "has_update": true,
    "update_type": "force",
    "latest_version": "1.1.0",
    "latest_build_number": "110",
    "min_supported_version": "1.0.0",
    "min_supported_build_number": "100",
    "title": "重要更新",
    "description": "本次更新包含重要的安全修复，请升级后继续使用。",
    "release_notes": "1. 修复了交易页面偶发崩溃问题\n2. 优化了行情列表加载速度\n3. 新增TON链充值支持",
    "download_url": {
      "ios": "https://apps.apple.com/app/id123456789",
      "android": "https://play.google.com/store/apps/details?id=com.detrade.app"
    },
    "android_apk_url": "https://cdn.detrade.com/app/detrade-v1.1.0.apk",
    "is_critical": true,
    "publish_time": "2026-05-28T10:00:00Z"
  }
}
```

#### 5.1.4 关键字段产品含义

| 字段 | 产品含义 | 取值说明 |
|------|---------|---------|
| `has_update` | 是否有新版本可更新 | `true` = 有新版本，`false` = 已是最新 |
| `update_type` | 更新策略类型 | `force` = 强制更新（阻断使用）<br>`optional` = 可选更新（可稍后处理）<br>`silent` = 静默（不主动提示） |
| `min_supported_version` | 最低支持版本 | 低于此版本的 App 将被强制要求更新，否则无法继续使用核心功能 |
| `is_critical` | 是否紧急更新 | `true` 时即使用户关闭弹窗也会在下一次操作时再次弹出 |
| `android_apk_url` | Android 直链下载 | 用于中国大陆等无法访问 Google Play 的地区，提供 APK 直接下载 |

### 5.2 客户端版本检查机制

#### 5.2.1 检查时机

| 时机 | 说明 | 频率限制 | 是否影响性能 |
|------|------|---------|-------------|
| App 冷启动 | 用户首次打开 App | 延迟 5 秒执行 | 低（延迟执行） |
| App 热启动 | 用户从后台切回前台 | 每小时最多 1 次 | 低 |
| 手动检查 | 用户在「设置-关于」点击「检查更新」 | 无限制 | 低 |
| 定时轮询 | 后台定时检查 | 每 6 小时 1 次 | 极低 |

#### 5.2.2 性能保护机制

| 机制 | 说明 |
|------|------|
| 延迟执行 | 冷启动后延迟 5 秒再请求，不影响首屏加载 |
| 超时控制 | 请求超时时间 5 秒，超时则跳过本次检查 |
| 降级处理 | 请求失败不影响 App 正常使用，下次启动再检查 |
| 本地缓存 | 检查结果缓存 6 小时，避免频繁请求 |

### 5.3 更新类型定义

| 更新类型 | 产品行为 | 适用场景 | 用户是否可以跳过 |
|---------|---------|---------|----------------|
| **强制更新** | 弹出全屏遮罩弹窗，用户必须点击更新按钮跳转商店，无法使用 App 其他功能 | 安全漏洞修复、重大 bug、不兼容旧版本的 API 变更 | 否 |
| **可选更新** | 弹出弹窗展示更新内容，用户可选择「立即更新」或「稍后更新」 | 新功能上线、体验优化、非紧急问题修复 | 是 |
| **静默** | 不在客户端主动展示弹窗，仅在后管记录版本信息，供手动检查更新时对比 | 内部测试版本、小范围验证 | - |

### 5.4 更新弹窗交互设计

#### 5.4.1 强制更新弹窗（不可关闭）

**交互规则**:

| 规则项 | 说明 |
|--------|------|
| 弹窗层级 | 覆盖全屏，置于最顶层 |
| 关闭方式 | 不可关闭，不显示关闭按钮 |
| 点击遮罩 | 点击弹窗外区域无效 |
| 物理返回键 | Android 物理返回键无效（不退出 App） |
| 更新按钮 | 点击后跳转对应应用商店（iOS → App Store，Android → Google Play 或 APK 下载） |
| 返回 App 后 | 用户从商店返回 App 后再次检查版本，若仍未更新则继续展示弹窗 |
| 多语言 | 弹窗文案支持多语言，根据用户当前使用语言展示 |

#### 5.4.2 可选更新弹窗（可关闭）

**交互规则**:

| 规则项 | 说明 |
|--------|------|
| 弹窗层级 | 普通弹窗层级 |
| 关闭方式 | 可点击右上角 ✕ 关闭 |
| 点击遮罩 | 点击弹窗外区域可关闭 |
| 物理返回键 | Android 物理返回键可关闭 |
| 稍后更新按钮 | 关闭弹窗，用户可正常使用 App |
| 立即更新按钮 | 点击后跳转对应应用商店 |
| 下次启动 | 下次启动时仍会展示（除非用户已更新） |
| 多语言 | 弹窗文案支持多语言，根据用户当前使用语言展示 |

#### 5.4.3 手动检查更新入口

**入口位置**: 「我的」→「设置」→「关于 DeTrade」→「检查更新」

**交互流程**:

```
用户点击「检查更新」
    │
    ▼
展示 loading 状态（按钮变为不可点击）
    │
    ▼
请求版本检查接口
    │
    ├── 请求失败 → 提示「检查失败，请稍后重试」
    │
    ├── 已是最新版本 → 提示「当前已是最新版本」
    │
    ├── 有可选更新 → 展示可选更新弹窗
    │
    └── 有强制更新 → 展示强制更新弹窗
```

### 6.3 新建版本推送页面

#### 6.3.1 字段详细说明

**A. 基础信息（必填）**

| 字段名 | 类型 | 必填 | 校验规则 | 说明 | 填写示例 |
|--------|------|------|---------|------|---------|
| `platform` | 单选 | 是 | 必选一项 | 目标平台 | iOS / Android / 双平台 |
| `version` | 文本 | 是 | 格式 `x.y.z`，x/y/z 为数字 | 目标版本号（语义化版本） | `1.1.0` |
| `build_number` | 数字 | 是 | 正整数 | 目标构建号（与上传到商店的构建号一致） | `110` |

**B. 更新策略（必填）**

| 字段名 | 类型 | 必填 | 说明 | 选项 | 默认值 |
|--------|------|------|------|------|--------|
| `update_type` | 单选 | 是 | 更新类型 | 强制更新 / 可选更新 / 静默 | 可选更新 |
| `min_supported_version` | 文本 | 是 | 最低支持版本，低于此版本强制更新 | 格式 `x.y.z` | 当前最新版本 |
| `is_critical` | 开关 | 是 | 是否紧急更新（开启后弹窗不可关闭） | 开 / 关 | 关 |

**C. 更新内容（必填）**

| 字段名 | 类型 | 必填 | 字符限制 | 说明 | 填写示例 |
|--------|------|------|---------|------|---------|

| `description` | 多行文本 | 是 | 最多 200 字 | 更新描述摘要，展示在弹窗正文 | `本次更新包含重要的安全修复，请升级后继续使用。` |
| `release_notes` | 多行文本 | 是 | 最多 1000 字 | 详细更新日志，支持换行 | `1. 修复了交易页面偶发崩溃问题\n2. 优化了行情列表加载速度\n3. 新增TON链充值支持` |

**D. 下载链接（按平台条件必填）**

| 字段名 | 类型 | 必填条件 | 校验规则 | 说明 | 填写示例 |

**E. 推送策略（可选）**

| 字段名 | 类型 | 必填 | 取值范围 | 说明 | 默认值 |

| `target_country` | 多选 | 否 | 多选，留空表示全球 | 目标国家/地区 | 全球 |
| `target_language` | 多选 | 否 | 多选，留空表示所有语言 | 目标语言 | 所有语言 |
| `start_time` | 日期时间 | 否 | 不能早于当前时间 | 生效时间，留空表示立即生效 | 立即生效 |
| `end_time` | 日期时间 | 否 | 不能早于 start_time | 失效时间，留空表示永久有效 | 永久有效 |

| 模块 | 内容 |
|------|------|
| 基本信息 | 版本号、构建号、目标平台、更新类型、最低支持版本、紧急更新 |
| 更新内容 | 弹窗标题、更新描述、更新日志 |
| 下载链接 | iOS 链接、Android 链接、APK 直链 |
| 推送策略 | 灰度比例、目标地区、目标语言、生效时间、失效时间 |
| 推送数据 | 已推送用户数、弹窗展示次数、用户点击更新数、用户点击稍后数 |
| 操作记录 | 发布时间、发布人、灰度调整记录等 |

#### 6.4.2 操作按钮规则

| 当前状态 | 可执行操作 | 操作说明 | 二次确认 |
|---------|-----------|---------|---------|
| 草稿 | 编辑 / 发布 / 删除 | 编辑可修改所有字段；发布变为生效中；删除需确认 | 删除需确认 |
| 生效中 | 暂停 / 查看 | 暂停后用户不再收到更新提示 | 暂停需确认 |
| 灰度中 | 全量 / 暂停 / 查看 | 全量将灰度设为 100%；暂停停止推送 | 全量和暂停均需确认 |
| 已暂停 | 恢复 / 下架 / 查看 | 恢复推送；下架后不可恢复 | 下架需确认 |
| 已下架 | 查看 | 仅可查看，不可操作 | - |

## 七、灰度发布策略

### 7.1 推荐三阶段灰度发布

| 阶段 | 推送比例 | 建议持续时长 | 观察指标 | 操作 |
|------|---------|-------------|---------|------|
| **第一阶段** | 10% | 2-4 小时 | 用户反馈、崩溃率 | 无明显负面反馈则进入下一阶段 |
| **第二阶段** | 50% | 4-8 小时 | 用户反馈、更新转化率 | 无明显负面反馈则全量 |
| **第三阶段** | 100% | 持续 | 常规监控 | - |

### 7.2 灰度调整操作

| 操作 | 说明 |
|------|------|
| 调整比例 | 在后管版本详情页可实时调整灰度比例 |
| 暂停推送 | 可随时暂停推送 |
| 全量推送 | 全量推送后无法降低灰度比例（只能下架） |

### 7.3 异常情况处理

| 异常场景 | 处理策略 | 后管操作 |
|---------|---------|---------|
| 新版本发现严重 bug | 立即暂停推送，下架该版本 | 后管点击「暂停」→「下架」 |
| 用户投诉激增 | 暂停推送，排查问题 | 后管点击「暂停」 |
| 商店审核未通过 | 下架版本，等审核通过后重新发布 | 后管点击「下架」 |
| 紧急安全漏洞需修复 | 发布强制更新版本，设最低支持版本 | 新建版本，选「强制更新」 |

## 十三、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 商店审核延迟 | 新版本无法及时上线 | 提前提交审核，预留审核时间 |
| 新版本发现严重 bug | 用户受到影响 | 后管可快速暂停/下架版本 |
| 版本检查接口不可用 | 用户收不到更新提示 | 接口降级不影响 App 使用，下次启动重试 |
| APK 直链被劫持 | 用户下载到恶意 APK | APK 签名校验，HTTPS 传输 |
| 用户不更新 | 旧版本用户继续使用 | 设最低支持版本强制更新 |
