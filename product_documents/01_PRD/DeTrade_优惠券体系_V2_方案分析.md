## 1. 现有方案分析 (Current Proposal Analysis)

### 1.1 文档概览
您提供的 Notion 文档定义了一个基础的优惠券体系，主要包含两种券类型：
1.  **现金券 (Cash Voucher)**: 直接增加余额，可交易、可提现（通常有限制）。
2.  **抵扣券 (Deduction Voucher)**: 抵扣交易本金或亏损。
同时定义了券的状态管理、发放场景（新客/召回/亏损补偿）以及基础的 ROI 分析指标。

## 2. 完善后的优惠券体系方案 (Enhanced Coupon System V2)

基于竞品分析，建议将优惠券体系重构为 **5 大核心券种**，覆盖用户生命周期的不同阶段。

### 2.1 核心券种定义 (Coupon Types)

#### Type A: 体验金 (Futures Trial Fund) - *拉新利器*
*   **定义**: 虚拟资金，仅用于合约/二元期权开仓。
*   **权益**: **盈利可提现** (需扣除体验金本金)，**亏损平台承担**。
*   **有效期**: 短期 (e.g., 3-7天)，过期回收。
*   **核心规则**:
    *   **不可提现**: 体验金本身不可提现，不可划转。
    *   **优先扣除**: 发生亏损时，优先扣除体验金，再扣除自有本金。
    *   **杠杆限制**: 最高只能开 20x (防止高倍赌博)。
    *   **回收机制**: 用户发起提现时，系统自动回收剩余体验金。

#### Type B: 手续费抵扣券 (Trading Fee Rebate) - *促活利器*
*   **定义**: 用于抵扣现货/合约产生的交易手续费。
*   **权益**: 产生手续费时，系统自动退还等额 USDT 到现货账户 (Cashback 模式) 或 直接抵扣 (Direct Deduct 模式)。
*   **优势**: 成本低 (平台少赚点而已)，用户感知强。

#### Type C: 亏损包赔券 (Loss Coverage Voucher) - *召回/安抚*
*   **定义**: 用于抵扣特定订单的**已实现亏损**。
*   **场景**: 用户爆仓或大额亏损后，系统自动发放，安抚情绪。
*   **规则**:
    *   仅限合约/二元期权。
    *   有赔付上限 (Cap)，例如“赔付 10 USDT 以内的亏损”。
    *   生效方式: 订单平仓后结算，若亏损，返还等额 USDT。

#### Type D: 现金券 (Cash Voucher / Token Voucher) - *高价值奖励*
*   **定义**: 真正的真金白银。
*   **场景**: 邀请排行榜第一名、重大Bug提交奖励。
*   **权益**: 无门槛，可直接提现，可交易。
*   **风控**: 需极高权限审批 (CEO/CFO)。

#### Type E: 赠金 (Bonus) - *入金激励*
*   **定义**: 充值赠送的资金 (Deposit Bonus)。
*   **权益**: 可作为保证金交易，**不可提现**。需完成特定交易量 (Turnover) 后才可转化为现金。

### 2.2 风险点与规避策略 (Risk & Mitigation)

这是您最关心的部分，以下是针对每种券的深度风控设计：

| 风险点 | 风险描述 | **规避策略 (Mitigation Strategy)** |
| :--- | :--- | :--- |
| **对敲套利** (Hedging) | 羊毛党注册两个账号 (A/B)，各领 100U 体验金。A 开多，B 开空。必有一方大赚，一方归零。套走盈利。 | 1. **KYC 限制**: 领取体验金必须完成 KYC Lv.1。<br>2. **同设备/IP 互斥**: 同一设备/IP 只能领一次。<br>3. **开仓限制**: 体验金订单禁止双向持仓。<br>4. **提现风控**: 提现时检查交易对手方，若发现对手方是关联账号，冻结资金。 |
| **高杠杆爆仓** | 用户拿免费体验金开 100x 杠杆赌运气，输了是平台的，赢了提走。 | **杠杆上限**: 体验金订单最高仅允许 **10x - 20x** 杠杆。 |
| **手续费刷单** | 代理商自己开小号，领“手续费抵扣券”，然后疯狂刷单赚取代理返佣。 | **返佣剔除**: 使用手续费抵扣券产生的交易量，**不计算**在代理商返佣基数内。 |
| **提现套现** | 用户充值 1000U，领 100U 赠金，然后不交易直接提现 1000U 本金，留 100U 赠金慢慢玩。 | **本金强挂钩 (Clawback)**: 提现本金时，系统按比例**自动销毁**剩余的赠金/体验金。 |
| **囤积倒卖** | 批量注册账号领券，然后将账号出售。 | **有效期管理**: 所有券必须设置较短的有效期 (3-7天)，过期作废，增加倒卖的时间成本。 |

### 2.3 数据库设计建议 (Schema)

需要两张核心表来管理复杂的券状态。

**1. 优惠券定义表 (`coupon_templates`)**
*   `type`: (Trial_Fund, Fee_Rebate, Loss_Cover, Cash)
*   `amount`: 面值
*   `leverage_limit`: 杠杆限制
*   `product_scope`: 适用产品 (Spot, Futures, Binary)
*   `valid_days`: 有效期天数

**2. 用户优惠券表 (`user_coupons`)**
*   `user_id`
*   `status`: (Available, Used, Expired, Locked)
*   `balance`: 剩余余额 (针对部分使用的场景)
*   `redeemed_order_id`: 关联的订单ID
*   `unlock_progress`: 解锁进度 (针对需交易量解锁的赠金)

## 3. 总结
V2 方案将模糊的“现金/抵扣券”拆解为 **体验金、手续费券、亏损券、赠金** 四大类，对标 Binance/Bybit 的成熟体系。
最核心的改进在于**风控侧**：引入了 **“提现回收机制 (Clawback)”** 和 **“返佣剔除”**，从根本上杜绝了羊毛党和代理商的套利空间。
