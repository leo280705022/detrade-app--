# DeTrade 用户分层体系 PRD v2.0

## 1. 文档概述

### 1.1 版本说明
本文档是 [DeTrade 用户分层设计方案 v1.0](../../../DeTrade_用户分层设计方案_v1.0.md) 的升级版本，在原有 6 层价值分层（SS/S/A/B/C/R）的基础上，**新增 VIP 等级体系（1-10 级）** 和 **用户生命周期分层运营** 的完整设计，形成三套分层体系相互配合的统一用户分层框架。

### 1.2 三大分层体系关系

```
┌─────────────────────────────────────────────────────┐
│                    VIP 等级体系                        │
│              （用户可见，1-10 级，展示身份）             │
│              ┌───────────────────────┐                │
│              │   用户价值分层         │                │
│              │ (后端判定,SS/S/A/B/C/R)│               │
│              │  ┌─────────────────┐  │                │
│              │  │  生命周期分层     │  │               │
│              │  │(引入/成长/成熟/   │  │               │
│              │  │ 休眠/流失)        │  │              │
│              │  └─────────────────┘  │                │
│              └───────────────────────┘                │
└─────────────────────────────────────────────────────┘
```

| 体系 | 面向对象 | 更新频率 | 核心作用 |
|------|----------|----------|----------|
| **VIP 等级体系** | 用户可见 | 每日 | 身份展示、权益激励、升级目标 |
| **用户价值分层** | 内部运营 | SS/S:日 / A/B/C:周 / R:实时 | 精准运营、差异化策略 |
| **生命周期分层** | 内部运营 | 每日 | 阶段识别、触达策略 |

#### 2.3.2 升级判定流程

```
每日 UTC 00:00 执行：
1. 采集用户近 30 天资产快照和交易数据
2. 计算当前 VIP 评分 = 资产分(40%) + 交易分(40%) + 活跃分(20%)
3. 若评分满足升级阈值且持续满足时间条件，自动升级
4. 触发升级通知（App Push + 站内信 + 邮件）
5. 同步权益到各子系统
```

#### 2.3.3 VIP 保级规则

| 规则 | 说明 |
|------|------|
| **考核周期** | VIP 1-5：每月评估；VIP 6-8：每 2 月评估；VIP 9-10：每 3 月评估 |
| **保级标准** | 考核周期内，资产和手续费均不低于当前等级门槛的 80% |
| **缓冲期** | 不达标后给予 7 天缓冲期，期间完成保级任务可维持 |
| **保级任务** | 充值差额 × 2 或 完成手续费差额 × 3 |
| **降级幅度** | 降至满足条件的最高等级（最多降 1 级/周期） |

### 2.5 VIP 0（新手体验卡）

为促进新用户快速体验 VIP 权益：

| 触发条件 | 权益 | 有效期 |
|----------|------|--------|
| 注册自动发放 | VIP 1 体验卡 | 7 天 |

| 完成新手全部任务 | VIP 3 体验卡 | 3 天 |
| 邀请 3 人注册 | VIP 2 体验卡 | 7 天 |

**体验卡规则**：
- 体验卡到期后自动恢复实际 VIP 等级
- 体验卡期间产生的交易数据可计入正式升级考核
- 同一用户最多同时持有一张体验卡
- 体验卡不可叠加，取最高等级生效

## 3. 用户生命周期分层运营

### 3.1 生命周期阶段定义

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  引入期   │───→│  成长期   │───→│  成熟期   │───→│  休眠期   │───→│  流失期   │
│ (Onboard)│    │ (Growth) │    │(Maturity)│    │(Dormant) │    │ (Churn)  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
      ↑                                                              │
      └──────────────── 回流 (Resurrection) ←────────────────────────┘
```

### 3.2 各阶段判定标准

#### 引入期（注册 0-7 天或未完成首充）
- 注册时间 ≤ 7 天 **或** 未完成首充
- 对应价值分层：C 级
- 对应 VIP 等级：0
- 阶段标签：`Onboarding`

#### 成长期（7-30 天，有交易行为，资产积累中）
- 注册时间 7-30 天
- 已完成首充和首单
- 资产 < 5,000 U
- 对应价值分层：C→B 级
- 对应 VIP 等级：1-2
- 阶段标签：`Growth`

#### 成熟期（30 天+，稳定活跃）
- 注册时间 > 30 天
- 30 天活跃天数 ≥ 10 天
- 有持续交易行为
- 对应价值分层：B/A/S/SS 级
- 对应 VIP 等级：3-10
- 阶段标签：`Mature`

#### 休眠期（连续 7-30 天未登录）
- 连续未登录 7-30 天
- 触发休眠预警
- 对应价值分层：维持原分层
- 阶段标签：`Dormant_7d` / `Dormant_15d` / `Dormant_30d`

#### 流失期（连续 30 天+未登录）
- 连续未登录 > 30 天
- 或连续 60 天无交易行为
- 阶段标签：`Churn_30d` / `Churn_60d` / `Churn_90d`

### 3.3 分阶段运营策略

#### 3.3.1 引入期运营

| 天数 | 运营动作 | 触发条件 | 目标 |
|------|----------|----------|------|
| Day 0 | 新人欢迎弹窗 + VIP1 体验卡 | 注册成功 | 建立第一印象 |
| Day 0 | 模拟交易引导（1000U 模拟金） | 首次登录 | 降低交易认知门槛 |
| Day 1 | Push：新手任务提醒 | 未开始新手任务 | 引导任务体系 |
| Day 2 | Push：首充翻倍提醒 | 未充值 | 促成首充 |
| Day 3 | 短信：限时体验金即将过期 | 有登录无充值 | 制造紧迫感 |
| Day 5 | Push：一键跟单教程 | 有充值未交易 | 促成首单 |
| Day 7 | Push：新手专属盲盒 | 完成首单 | 留存刺激 |

#### 3.3.2 成长期运营

| 触发场景 | 运营策略 | 执行方式 |
|----------|----------|----------|
| 首次盈利 | 晒单引导弹窗 + 分享奖励 | App 弹窗 |
| 首次亏损 | 跟单功能推荐 + 策略分析推送 | Push |
| 连续 3 天交易 | 交易打卡奖励 | 自动发放 |
| 资产突破 1,000 U | VIP 升级预告 | 站内信 |
| 爆仓 | 亏损安抚券 + 复活弹窗 | Push + 弹窗 |
| 7 天未交易 | 热门币种推送 + 交易赛邀请 | Push |

#### 3.3.3 成熟期运营

| 用户特征 | 运营策略 |
|----------|----------|
| A 级用户（VIP 4-5） | VIP 升级提醒、新功能内测资格、交易赛定向邀请 |
| S 级用户（VIP 6-8） | 1v1 费率谈判、线下沙龙邀请、定制礼品 |
| SS 级用户（VIP 9-10） | 私人管家、季度策略会、平台决策建议权 |
| 活跃度高 | 邀请加入社区 KOL 计划 |
| 活跃度下降 | 推送新产品功能介绍、限时费率优惠 |

#### 3.3.4 休眠期召回

| 未登录天数 | 触达方式 | 召回内容 |
|-----------|----------|----------|
| 7 天 | App Push | "市场大涨！BTC 突破新高" |
| 15 天 | App Push + 短信 | 回归礼包：手续费 5 折券 × 3 |
| 30 天 | 短信 + 邮件 | 回归大礼包：20U 体验金 + VIP 体验卡 |
| 60 天 | 邮件 + 电话（VIP 6+） | 专属回归福利：50U 体验金 + 限时 VIP+1 |
| 90 天 | 邮件（最后一次） | 账户数据即将归档提醒 |

#### 3.3.5 流失用户处置

| 条件 | 处置动作 |
|------|----------|
| 60 天未登录 & 资产 = 0 | 标记为流失，停止 Push/短信触达 |
| 90 天未登录 & 资产 = 0 | UID/用户名释放回收池 |
| 180 天未登录 & 资产 > 0 | 邮件通知资产处理（提现或划转），30 天后冻结 |
| 任何休眠用户 VIP 6+ | 升级为电话触达，专属经理跟进 |

### 3.4 生命周期与 VIP 的交叉运营

| 生命周期 × VIP | 低 VIP（0-2） | 中 VIP（3-5） | 高 VIP（6-10） |
|---------------|-------------|-------------|---------------|
| **引入期** | 新手任务 + 跟单引导 | - | - |
| **成长期** | 交易打卡 + 亏损安抚 | 充值阶梯奖励 | 定制费率咨询 |
| **成熟期** | 交易赛 + 社群 | VIP 升级提醒 | 线下活动 + 1v1 |
| **休眠期** | Push + 回归礼包 | Push + 短信 + 回归礼包 | 电话 + 专属召回方案 |
| **流失期** | 低成本邮件召回 | 高价值召回礼包 | 专属经理电话跟进 |

### 4.2 手动分层调整

| 操作 | 权限 | 说明 |
|------|------|------|
| **手动升级** | 运营主管 + 审批 | 将用户手动提升至指定分层/VIP，需填写原因 |
| **手动降级** | 运营主管 | 将用户手动降至指定分层/VIP，需填写原因（通常风控触发） |
| **分层冻结** | 风控专员 | 冻结用户分层（不变更），适用于调查期 |
| **白名单** | 运营总监 | 将用户加入白名单，不受自动降级影响 |

**手动调整记录**：
- 所有手动调整必须记录操作人、操作时间、调整前后、调整原因
- 手动调整后需经上一级审批（白名单需运营总监审批）
- 调整记录永久保存，支持审计追溯

|--------|------|-----------|
| 分层判定阈值 | 各层级资产/交易/活跃门槛 | 资产门槛、手续费门槛、活跃天数 |
| VIP 升级条件 | 各 VIP 等级的升级条件 | 资产条件、交易条件、时间条件 |
| 权益配置 | 各分层/VIP 的权益参数 | 费率、返水比例、签到系数、提现额度 |
| 更新频率 | 各分层更新策略 | SS/S:日/A/B/C:周/R:实时 |
| 降级缓冲 | 降级保护规则 | 缓冲期天数、保级任务要求 |

### 4.4 操作日志与审计

| 日志类型 | 记录内容 |
|----------|----------|
| 自动分层变更 | 用户 ID、变更前后分层、变更时间、触发指标数据 |
| 手动分层调整 | 操作人、操作时间、调整前后、原因、审批人 |
| 权益配置变更 | 配置项、变更前后值、操作人、时间 |
| 异常预警 | 异常类型（如某层级用户数突变）、时间、关联数据 |

## 6. 技术实现方案

### 6.1 核心数据表

```sql
-- VIP 等级表（新增）
CREATE TABLE user_vip (
    user_id BIGINT PRIMARY KEY,
    current_vip INT NOT NULL DEFAULT 0,        -- VIP 0-10
    vip_score INT,                              -- VIP 综合评分
    vip_upgraded_at TIMESTAMP,                  -- 最近升级时间
    vip_expires_at TIMESTAMP,                   -- VIP 体验卡过期时间（无则为NULL）
    vip_card_source VARCHAR(50),                -- 体验卡来源：register/first_deposit/newbie_task
    vip_evaluation_at TIMESTAMP,                -- 下次评估时间
    vip_history JSON,                           -- VIP 变更历史
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 用户生命周期表（新增）
CREATE TABLE user_lifecycle (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id BIGINT,
    lifecycle_stage VARCHAR(20) NOT NULL,       -- onboarding/growth/mature/dormant/churn
    stage_entered_at TIMESTAMP,                 -- 进入当前阶段时间
    stage_duration_days INT,                    -- 当前阶段持续天数
    previous_stage VARCHAR(20),                 -- 上一阶段
    last_active_at TIMESTAMP,                   -- 最近活跃时间
    last_trade_at TIMESTAMP,                    -- 最近交易时间
    dormant_alert_sent BOOLEAN DEFAULT FALSE,   -- 是否已发送休眠预警
    churn_alert_sent BOOLEAN DEFAULT FALSE,     -- 是否已发送流失预警
    recall_count INT DEFAULT 0,                 -- 召回次数
    last_recall_at TIMESTAMP,                   -- 最近召回时间
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_lifecycle (lifecycle_stage),
    INDEX idx_user (user_id)
);

-- 分层变更日志表（新增）
CREATE TABLE user_tier_change_log (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id BIGINT,
    change_type VARCHAR(20) NOT NULL,           -- auto_upgrade/auto_downgrade/manual_upgrade/manual_downgrade/freeze
    from_tier VARCHAR(10),                      -- 变更前价值分层
    to_tier VARCHAR(10),                        -- 变更后价值分层
    from_vip INT,                               -- 变更前 VIP
    to_vip INT,                                 -- 变更后 VIP
    change_reason TEXT,                         -- 变更原因/触发指标
    operator_id BIGINT,                         -- 操作人ID（自动变更时为0）
    approval_id BIGINT,                         -- 审批人ID
    snapshot_data JSON,                         -- 变更时的指标快照
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_user (user_id),
    INDEX idx_change_type (change_type)
);
```

### 6.3 分层判定引擎

```
【引擎架构】

┌─────────────────────────────────────────────┐
│                  Cron Scheduler               │
│  SS/S级: 每日 UTC 00:00                      │
│  A/B/C级: 每周一 UTC 00:00                   │
│  R级: 实时触发（风控事件）                     │
└─────────────────┬───────────────────────────┘
                  ▼
┌─────────────────────────────────────────────┐
│              Data Aggregator                  │
│  采集：资产快照 + 交易数据 + 活跃日志 + 风控数据 │
└─────────────────┬───────────────────────────┘
                  ▼
┌─────────────────────────────────────────────┐
│              Tier Calculator                  │
│  价值分层判定 → VIP 等级计算 → 生命周期识别     │
└─────────────────┬───────────────────────────┘
                  ▼
┌─────────────────────────────────────────────┐
│             Change Detector                   │
│  对比上次结果，识别变更（升级/降级/阶段切换）    │
└─────────────────┬───────────────────────────┘
                  ▼
┌─────────────────────────────────────────────┐
│            Notification Engine                │
│  生成通知（Push/站内信/邮件）+ 同步权益          │
└─────────────────────────────────────────────┘
```
