## 一、需求背景与目标

### 1.1 业务背景

DeTrade 当前交易对展示存在以下核心问题：
- 所有交易对混杂排列，**无分类、无标签**，用户无法快速识别交易对类型
- 已关闭交易对与可交易交易对混排，视觉区分度不足
- 缺少 24H 成交量展示，用户无法判断流动性
- 后管系统中币种管理和交易对管理职责重叠，运营效率低
- 缺少系统性的分类/标签体系，无法支撑精细化运营

### 1.2 需求目标

| 目标 | 衡量指标 |
|------|---------|
| 提升用户找交易对效率 | 用户从进入交易页到找到目标交易对的平均时间降低 40% |
| 提升交易对流动性感知 | 展示 24H 成交额，帮助用户判断流动性 |
| 提升后管运营效率 | 交易对上架/下架操作时间降低 60%（批量操作+状态流转） |
| 支撑精细化运营 | 通过分类/标签体系实现差异化展示和营销 |

### 1.3 涉及端

- **Web 桌面端**：交易页交易对选择器
- **App 移动端**：交易对选择页面
- **H5 (Telegram Mini App)**：交易对选择页面（空间最受限）
- **后管 Admin**：币种管理 + 交易对管理 + 分类标签管理

| 问题 | 具体表现 | 影响等级 |
|------|---------|---------|
| 无分类体系 | 数字货币、传统金融、股票交易对混排 | P0 |

| 状态区分不足 | 已关闭交易对仅显示"市场已关闭"小字 | P1 |
| 缺少成交量 | 无 24H 成交额展示 | P1 |
| 排序维度单一 | 仅支持价格/涨跌幅排序 | P2 |
| 无子分类筛选 | 无法按 Meme/DeFi/半导体等细分筛选 | P0 |

### 3.2 后管系统现状

**当前菜单结构：**
```
币管理
├── 备用金概览
├── 货币管理 (Currency Manage)     ← 币种基础信息
├── 交易对配置 (Pair Config)        ← 与货币管理同页面，职责重叠
└── 交易对管理 (Pair Manage)        ← 与"交易对配置"功能高度重叠
├── 币账户管理
└── 预言机监控
```

**核心问题：**

| 问题类别 | 具体表现 | 影响 |
|---------|---------|------|
| **架构混乱** | 货币管理、交易对配置、交易对管理三个页面职责重叠 | 运营效率低，容易操作错误 |
| **数据模型缺失** | 币种和交易对未解耦，缺少分类/标签体系 | 前端无法实现分类展示 |
| **运营能力弱** | 无批量操作、无拖拽排序、无状态流转 | 上线/下架效率低 |
| **信息不完整** | 缺少 24H 量、流动性、关联交易对数等 | 无法做运营决策 |
| **前端无分类** | 所有交易对混排，无标签、无子分类 | 用户体验差 |

### 3.3 创建交易对表单问题

当前创建交易对表单存在以下问题：
- 字段过多且未分组，运营人员难以理解
- 资产类型（传统金融/数字货币/股票）与交易类型混淆
- 缺少分类和标签配置能力
- 任务配置（cron 表达式）与基础配置混在一起
- 缺少交易参数继承机制（应自动继承币种精度配置）

## 四、数据模型设计

### 4.1 核心概念解耦

```
─────────────┐     1:N     ──────────────────┐     N:1     ──────────────┐
│   Coin 币种  │ ────────→ │  TradingPair 交易对 │ ←───────── │  Category 分类 │
│  (BTC, ETH)  │            │  (BTCUSDT, ETHUSDT)│            │  (数字货币等)  │
└─────────────┘            ────────┬─────────┘            └──────────────┘
       │ 1:N                        │ N:M
       ↓                            ↓
┌─────────────┐            ┌──────────────┐
│  Network 链  │            │  Tag 标签     │
│ (ETH/BSC..) │            │ (Hot/0Fee等)  │
└─────────────┘            └──────────────┘
```

**关键设计原则：**
- 币种（Coin）和交易对（TradingPair）是两层独立实体
- 一个 Coin 可关联多条 Network（链），每条链独立控制充提
- 一个 TradingPair 可关联多个 Tag（标签）
- Category（分类）用于前端展示分组

### 4.2 Coin（币种）数据模型

```typescript
interface Coin {
  id: string;
  name: string;              // 全称：Bitcoin
  nameEn: string;            // 英文名：Bitcoin
  symbol: string;            // 代码：BTC
  icon: string;              // 图标 URL
  iconColor: string;         // 图标背景色：#F7931A

  // 基础属性
  assetType: 'crypto' | 'tradfi' | 'stock';  // 资产大类
  chain?: string;            // 所属链（仅 crypto）：ETH, BSC, SOL...
  contractAddress?: string;  // 合约地址（仅 crypto token）

  // 精度配置
  pricePrecision: number;    // 价格小数位数：2
  quantityPrecision: number; // 数量小数位数：6

  // 状态
  status: 'active' | 'suspended' | 'delisted';

  // 运营数据（只读）
  tradingPairCount: number;  // 关联交易对数量

  // 时间
  createdAt: string;
  updatedAt: string;
}
```

### 4.3 Network（链/网络）数据模型

```typescript
interface Network {
  id: string;
  coinId: string;            // 关联币种 ID
  name: string;              // 链名称：BTC / ETH / BSC / SOL / TRON
  chainType: string;         // 链类型：Mainnet / Testnet

  // 充提配置
  depositEnabled: boolean;   // 充值开关
  withdrawEnabled: boolean;  // 提现开关
  minDepositAmount: number;  // 最小充值量
  minWithdrawAmount: number; // 最小提现量
  withdrawFee: number;       // 提现手续费（固定值）
  withdrawFeeRate?: number;  // 提现手续费率（百分比，可选）
  depositConfirmations: number;  // 充值确认数
  withdrawConfirmations: number; // 提现确认数

  // Token 专属
  contractAddress?: string;  // 合约地址（ERC20/BEP20 等）

  // 状态
  status: 'active' | 'maintenance' | 'suspended';

  createdAt: string;
  updatedAt: string;
}
```

### 4.4 TradingPair（交易对）数据模型

```typescript
interface TradingPair {
  id: string;
  symbol: string;            // 交易对代码：BTCUSDT
  baseCoinId: string;        // 基础币种 ID（关联 Coin）
  quoteCoinId: string;       // 计价币种 ID（关联 Coin）
  displayName: string;       // 显示名称：BTC/USDT

  // 分类体系（核心）
  category: 'crypto' | 'tradfi' | 'stock';  // 一级分类
  subCategory?: string;      // 二级分类：Meme / 大宗商品 / 半导体 / ETF / 指数...

  // 标签系统（多标签）
  tags: string[];            // ['hot', '0fee', 'pre-ipo', 'new']

  // 排序与展示
  sortOrder: number;         // 排序权重（数字越小越靠前）
  isHot: boolean;            // 是否热门
  isFeatured: boolean;       // 是否推荐（首页展示）

  // 交易状态
  tradingStatus: 'pending' | 'active' | 'paused' | 'maintenance' | 'closed';

  // 交易参数
  minOrderAmount: number;    // 最小下单金额
  maxOrderAmount: number;    // 最大下单金额
  pricePrecision: number;    // 价格精度（默认继承币种）
  quantityPrecision: number; // 数量精度（默认继承币种）

  // 资金池（预测交易用）
  poolBalance: number;       // 资金池余额
  totalPoolAmount: number;   // 总持仓金额

  // 运营数据（只读，由系统计算）
  volume24h: number;         // 24H 成交额
  lastPrice: number;         // 最新价格
  priceChangePercent24h: number;  // 24H 涨跌幅
  fundingRate?: number;      // 资金费率（合约交易对）

  // 关闭信息
  closeTime?: string;        // 关闭时间（预测交易）
  closeReason?: string;      // 关闭原因

  // 时间
  createdAt: string;
  updatedAt: string;
}
```

## 五、前端交易对分类展示方案

### 5.1 整体信息架构

```
交易对列表
├── 搜索框（顶部固定）
├── 一级分类 Tab（资产类型）
│   ├── 全部
│   ├── 数字货币 (Crypto)
│   ├── 传统金融 (TradFi)
│   └── 股票 (Stock)
├── 二级筛选 Chips（状态/标签）
│   ├── 全部
│   ├── 热门
│   ├── 0 Fees
│   ├── 可交易
│   └── 已关闭
├── 子分类筛选（横向滚动 Chips）
│   ├── Meme / DeFi / Layer1 / AI / ...
│   ├── 大宗商品 / 外汇 / 指数 / ...
│   └── 科技股 / 半导体 / ...
├── 列表头（Web 端）
│   ├── 交易对 | 最新价格 | Chg% | 24H成交额 | 资金费率
└── 交易对列表
    └── 每行：[收藏星] [图标] [名称] [标签] | [最新价] [涨跌幅] [24H量] [资金费率]
```

### 5.2 Web 桌面端设计

#### 布局结构

```
┌──────────────────────────────────────────────────────────────┐
│  当前交易对：BTC/USDT    63,610.38   -1.63%   FR: 0.0087%    │  ← 顶部当前交易对信息
├──────────────────────────────────────────────────────────────┤
│  🔍 搜索交易对...                                             │  ← 搜索框
├──────────────────────────────────────────────────────────────┤
│  [全部] [数字货币] [传统金融] [股票]                           │  ← 一级分类 Tab
├──────────────────────────────────────────────────────────────┤
│  [全部] [热门] [0 Fees] [可交易] [已关闭]                     │  ← 状态/标签筛选 Chips
├──────────────────────────────────────────────────────────────┤
│  子分类: [全部]  Meme  DeFi  Layer1  AI  大宗商品 ...          │  ← 子分类筛选（横向滚动）
├──────────────┬──────────┬──────────┬──────────┬──────────────┤
│ 交易对        │ 最新价格  │ Chg%     │ 24H成交额 │ 资金费率     │  ← 列表头（可点击排序）
├──────────────┼──────────┼──────────┼──────────┼──────────────┤
│ ★ ₿ BTC/USDT [0Fees]   │ 63,610   │ -1.63%  │ 2.8B      │ 0.0087%      │
│ ☆ Ξ ETH/USDT [0Fees]   │ 1,856    │ -3.54%  │ 1.5B      │ 0.0065%      │
│ ☆ ◎ SOL/USDT [0Fees]   │ 75.31    │ -2.18%  │ 890M      │ 0.0043%      │
│ ...                                                             │
└──────────────┴──────────┴──────────┴──────────┴──────────────┘
```

#### 关键交互

1. **一级 Tab 切换**：切换资产大类，URL 同步参数 `?category=crypto`
2. **筛选 Chip 切换**：单选模式，点击切换筛选条件
3. **子分类筛选**：横向滚动 Chips，点击筛选对应子分类
4. **列表排序**：点击列表头切换升序/降序/默认
5. **收藏功能**：点击星标收藏/取消收藏，收藏的交易对置顶显示
6. **已关闭交易对**：显示倒计时（如 `05h25m`），整体透明度降低至 50%
7. **标签展示**：标签内嵌在交易对名称右侧，使用彩色小圆角矩形
8. **资金费率**：仅合约交易对展示，正值绿色、负值红色

```

  │       │      └─ 交易对名称                │            │        └─ 24H成交额
```

## 七、状态流转设计

### 7.1 交易对状态机

参考 Binance 的 5 种状态和 Bybit 的下架流程设计：

```
                    创建
                     │
                     ▼
              ┌─────────────┐
              │   待上线      │ ← 新创建的交易对默认状态
              │  (pending)   │
              ──────┬──────┘
                     │ 运营手动上线
                     ▼
              ┌─────────────┐
         ┌───→│   交易中      │
         │    │  (active)    │
         │    └──────┬──────┘
         │           │ 运营手动暂停 / 系统自动暂停
         │           ▼
         │    ┌─────────────┐
         │    │   已暂停      │
         │    │  (paused)    │
         │    └──────┬──────┘
         │           │ 运营手动恢复
         └───────────┘
                     │ 运营手动关闭 / 到期自动关闭 / 触发自动下架条件
                     ▼
              ┌─────────────┐
              │   已关闭      │ ← 终态，不可逆转
              │  (closed)    │
              └─────────────┘
```

**状态规则：**

| 状态 | 前端展示 | 可交易 | 可编辑字段 | 说明 |
|------|---------|--------|-----------|------|
| 待上线 (pending) | 不展示 | 否 | 所有字段 | 新创建的交易对默认状态 |
| 交易中 (active) | 正常展示 | 是 | 仅风控参数和标签 | 正常交易状态 |
| 已暂停 (paused) | 展示（灰色提示） | 否 | 所有字段 | 运营主动暂停，可恢复 |
| 已关闭 (closed) | 展示（半透明+倒计时） | 否 | 不可编辑 | 终态，不可逆转 |

### 7.2 自动下架条件（参考 Bybit）

| 条件 | 触发动作 |
|------|---------|
| 价格到达最小精度的 50 倍 | 发送预警通知给运营 |
| 价格到达最小精度的 20 倍 | 系统自动下架，无需另行通知 |
| 24H 成交额连续 7 天为 0 | 发送预警通知 |
| 项目方停止运营/重大负面 | 运营手动触发下架流程 |

### 7.3 币种状态与交易对状态的联动

| 事件 | 联动效果 |
|------|---------|
| 币种暂停 | 该币种关联的所有交易对自动暂停 |
| 币种下架 | 该币种关联的所有交易对自动关闭 |
| 某链维护 | 仅影响该链充提，不影响交易对交易 |
| 交易对暂停 | 仅该交易对不可交易，其他同币种交易对不受影响 |
| 交易对关闭 | 前端半透明展示，显示关闭倒计时 |

## 九、迁移方案

### 9.1 现有数据迁移

```sql
-- 1. 从现有交易对表提取币种信息，创建 Coin 记录
INSERT INTO coins (symbol, name, asset_type, status)
SELECT DISTINCT
  base_asset AS symbol,
  base_asset AS name,
  asset_type,
  'active' AS status
FROM trading_pairs;

-- 2. 为现有交易对分配分类
UPDATE trading_pairs SET category = asset_type;

-- 3. 为热门交易对添加标签
UPDATE trading_pairs SET tags = '["hot"]' WHERE is_hot = true;

-- 4. 为 0 Fees 交易对添加标签
UPDATE trading_pairs SET tags = CONCAT(tags, ',"0fee"') WHERE fee_rate = 0;
```
