# 交易大赛业务端 PRD V1.0

## 1. 概述

本文档定义交易大赛业务端（用户端/前端）的产品需求。用户可通过交易大赛活动中心浏览、查看、参与交易大赛，查看个人排名与获奖记录。

### 1.1 产品定位

- 交易大赛为**默认全员参与**机制，无需用户手动报名
- 只有满足参赛门槛的交易才会被计入排行榜
- 用户可在活动首页浏览所有进行中的交易大赛
- 用户可查看活动详情、排行榜、排名奖励
- 用户可在"我的排名"页面查看个人在所有大赛中的排名与获奖情况

### 1.2 产品目标

- 提升用户交易活跃度与粘性
- 通过排名与奖励机制激励用户交易
- 提供透明的排行与奖励信息展示
- 支持世界杯等主题营销活动的视觉运营

## 3. 页面结构

业务端包含以下页面：

1. **活动首页**（home）— 活动卡片列表、筛选、Banner
2. **活动详情页**（detail）— 完整活动信息、排名奖励、排行榜
3. **我的排名页**（myRanking）— 个人在所有大赛中的排名与获奖历史

## 9. 核心业务逻辑

### 9.1 默认全员参与

- 交易大赛采用**默认全员参与**机制
- 用户无需点击报名
- 满足参赛门槛的交易**自动**被计入排行榜统计

### 9.2 参赛门槛过滤

| 条件 | 逻辑 |
| --- | --- |
| 最小有效单笔金额 | 单笔交易金额 < 该值 → 不计入排行 |
| 最大有效单笔金额 | 单笔交易金额 > 该值 → 不计入排行 |
| 最低交易笔数 | 用户总有效交易笔数 < 该值 → 不参与排行 |

> 字段值为 0 时表示该项不构成限制。

### 9.3 排行榜排名方式

每个交易大赛在后管配置**单一**排名方式（rankBy），前端：
- 排行榜**固定**按该方式排序和展示
- **不提供**排名维度切换
- 仅展示该活动对应的单一指标列（如 rankBy=pnl 则只展示 PnL 列）
- 页面顶部显示"排名依据：X"标签

### 9.4 排名算法

| 算法 | 计算方式 | 计入排行条件 |
| --- | --- | --- |
| 盈亏额（PnL） | 统计用户盈利金额 | PnL ≤ 0 不计入 |
| 利润绝对值 | 盈利绝对值 + 亏损绝对值 | 恒为正数 |
| ROI | 盈亏金额 / 下单金额 | ROI ≤ 0 不计入 |
| 单笔 ROI | Tap Trading 玩法口径 | 单笔 ROI ≤ 0 不计入 |
| 胜率 | 盈利单数 / 下单总数 | 胜率 ≤ 0 不计入 |

### 9.5 奖励解锁

- 用户需**同时满足**"充值金额"和"真金交易笔数"两个条件
- 任一字段设为 0，表示该项不限制
- 两个都为 0 表示无解锁要求，按排名自动获得

### 9.6 奖励发放

| 模式 | 逻辑 |
| --- | --- |
| 自动发放 | 活动结束后，按配置的延期时间（0H/1H/1天）自动发放 |
| 手动发放 | 活动结束后需运营手动确认后发放 |

### 9.7 未登录状态

- 未登录用户可正常浏览活动列表、详情、排行榜
- 点击"立即参与"按钮 → 触发登录引导
- 不显示个人排名数据
