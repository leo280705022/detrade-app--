## 1. 问题陈述

**P0** 当前 admin 无法完整配置法币提现手续费和减免折扣。运营在设置提现规则时，需要在不同页面理解「币本位数量」「USDT 金额」「会员折扣」三套口径，入口分散且计算基数不统一，容易造成用户实际扣费与运营预期不一致。

| 现状问题 | 具体表现 | 业务影响 | 本次处理 |
|---------|---------|---------|---------|
| 无法设置法币提现手续费和折扣 | 币账户缺少完整手续费配置；会员管理的折扣逻辑与手续费基数脱节 | 运营无法按币种/账户精确控制提现成本，用户侧扣费解释困难 | 币账户新增提现手续费字段；会员仅设置折扣比例 |
| 最小/最大提现金额入口不统一 | 最小提现数量与金额类限制分散，最大限制缺失或不可见 | 配置遗漏会导致风控、客服和用户提示不一致 | 币账户统一配置数量上下限和 USDT 金额上下限 |
| 币本位数量与金额口径混用 | 用户提现的是币数量，但风控/额度常按 USDT 估值判断 | 同一币种价格波动时，运营不知道应看数量还是金额 | 保留币本位数量字段，同时新增 USDT 金额字段 |
| 会员提现手续费减免折扣率逻辑错误 | 折扣可能被理解为减免比例或手续费覆盖值 | 不同会员等级扣费结果不稳定，无法对账 | 折扣率定义为应付比例：最终手续费 = 币账户手续费 × 折扣比例 |

> 测试后管地址已访问，当前能观察到后管框架、页签、左侧菜单和风控列表；直接访问币账户路由时测试环境出现连接中断。本文对现有页面细节的判断结合已归档的币管理资料和本次业务规则，未观察到的字段以「待确认」标记。

## 3. 范围边界

### 本次做

币账户新增提现手续费、最小提现数量、最大提现数量、最小提现金额（USDT）、最大提现金额（USDT）。列表、详情、新增、编辑、操作日志需要同步展示或记录这些字段。

会员管理中的提现手续费减免折扣率改为折扣比例。页面文案、校验和计算预览必须让运营明确：折扣比例是最终应付比例，不是减免比例，也不是独立手续费。

### 本次不做

不重构完整币管理信息架构，不处理充值手续费，不改变用户提现审核风控流程，不新增前台提现页面大改版。前台只需消费新的配置并保持提示一致。

不在会员管理里维护币种级手续费基数。这个取舍会减少会员侧自由度，但能避免同一用户在不同币种下出现不可解释的扣费差异。

## 4. 核心规则

### 4.1 字段口径

| 字段 | 归属入口 | 单位 | 含义 | 校验规则 |
|-----|---------|-----|------|---------|
| 提现手续费 | 币管理 / 币账户管理 | 对应币种数量 | 该币账户的基础提现手续费，也是会员折扣的计算基数 | 必填，≥ 0，精度不超过币种数量精度 |
| 最小提现数量 | 币管理 / 币账户管理 | 对应币种数量 | 用户单笔提现的最小币本位数量 | 必填，> 0，≤ 最大提现数量 |
| 最大提现数量 | 币管理 / 币账户管理 | 对应币种数量 | 用户单笔提现的最大币本位数量 | 必填，> 最小提现数量 |
| 最小提现金额 | 币管理 / 币账户管理 | USDT | 用户单笔提现按实时估值折算后的最小金额 | 必填，≥ 0，≤ 最大提现金额 |
| 最大提现金额 | 币管理 / 币账户管理 | USDT | 用户单笔提现按实时估值折算后的最大金额 | 必填，> 最小提现金额 |
| 提现手续费减免折扣率 | 用户管理 / 会员管理 | % | 会员等级应付手续费比例。100% 表示不减免，80% 表示支付 80% 手续费，0% 表示免手续费 | 必填，0%–100%，支持最多 2 位小数 |

### 4.2 手续费计算

```
基础提现手续费 = 币账户.提现手续费
会员折扣比例 = 会员等级.提现手续费减免折扣率
用户实际提现手续费 = 基础提现手续费 × 会员折扣比例
用户到账数量 = 提现数量 - 用户实际提现手续费
```

示例：BTC 币账户提现手续费为 `0.0005 BTC`，VIP2 折扣比例为 `80%`，则该用户提现 BTC 时实际手续费为 `0.0004 BTC`。如果折扣比例为 `0%`，实际手续费为 `0 BTC`。

### 4.3 额度判断

| 判断维度 | 判断方式 | 失败提示 | 备注 |
|---------|---------|---------|-----|
| 币本位数量下限 | 提现数量 ≥ 最小提现数量 | 单笔提现数量不能低于 X {币种} | 直接按用户输入数量判断 |
| 币本位数量上限 | 提现数量 ≤ 最大提现数量 | 单笔提现数量不能高于 X {币种} | 防止异常大额币数量 |
| USDT 金额下限 | 提现数量 × 当前估值 ≥ 最小提现金额 | 单笔提现折算金额不能低于 X USDT | 估值价格来源待技术确认 |
| USDT 金额上限 | 提现数量 × 当前估值 ≤ 最大提现金额 | 单笔提现折算金额不能高于 X USDT | 用于跨币种统一风控口径 |

> 数量限制和金额限制同时生效。只要任一维度不通过，提现提交不允许继续，并返回对应提示。这样会增加运营配置项，但换来跨币种风控口径一致。

## 5. 功能需求

### 5.1 币账户管理列表

| 模块 | 需求 | 优先级 | 说明 |
|-----|------|-------|-----|
| 筛选区 | 支持币种、账户类型、提现状态筛选 | P1 | 若现有页面已有筛选项，保留现状并补充账户类型/状态即可 |
| 列表字段 | 新增展示提现手续费、最小/最大提现数量、最小/最大提现金额（USDT） | P0 | 字段过多时可默认展示核心字段，其他字段放入详情或列设置 |
| 操作列 | 新增/编辑币账户时可配置完整提现规则 | P0 | 新增和编辑表单字段保持一致，避免入口不统一 |
| 状态识别 | 提现关闭时仍允许维护规则，但前台不允许提现 | P1 | 配置和开关解耦，便于提前准备规则 |

### 5.2 新增/编辑币账户

表单按「基础信息」「提现开关」「提现费用与额度」分组。提现费用与额度分组中必须同时展示币本位数量字段和 USDT 金额字段，字段旁用单位标识减少误填。

| 分组 | 字段 | 控件 | 必填 | 默认值 |
|-----|------|-----|-----|-------|
| 基础信息 | 币种、账户类型、网络/链、精度 | 下拉/输入框 | 按现有规则 | 沿用现有 |
| 提现开关 | 是否允许提现 | 开关 | 是 | 关闭或沿用现有默认 |
| 提现费用与额度 | 提现手续费 | 数字输入框 + 币种单位 | 是 | 待确认 |
| 提现费用与额度 | 最小提现数量、最大提现数量 | 数字输入框 + 币种单位 | 是 | 待确认 |
| 提现费用与额度 | 最小提现金额、最大提现金额 | 数字输入框 + USDT 单位 | 是 | 待确认 |
| 配置说明 | 费用公式预览 | 只读说明 | 否 | 根据输入实时变化 |

### 5.3 会员管理

会员管理中保留「提现手续费减免折扣率」字段，但调整解释和计算：该字段表示会员最终应付的手续费比例。页面需要展示「基数来自币账户」的提示，不允许在会员等级里单独配置某个币种的手续费基数。

| 页面位置 | 变更前风险 | 变更后要求 | 示例文案 |
|---------|----------|----------|---------|
| 会员等级列表 | 只展示折扣率，无法理解计算基数 | 列名调整为「提现手续费折扣比例」 | 80% = 支付基础手续费的 80% |
| 新增/编辑会员等级 | 运营可能填成减免比例 | 输入框下方展示规则说明和示例 | 基础手续费取币账户配置，0% 表示免手续费，100% 表示不减免 |
| 详情/预览 | 无法验证配置结果 | 提供示例币种的费用预览 | BTC 基础手续费 0.0005，折扣 80%，用户实际支付 0.0004 BTC |

### 5.4 操作日志与兼容

| 事项 | 要求 | 原因 |
|-----|------|-----|
| 操作日志 | 记录字段变更前后值、操作人、操作时间、变更入口 | 提现手续费属于资金相关配置，必须可追溯 |
| 历史数据 | 已有币账户缺失字段时，后台需提供迁移默认值或禁止保存前台可用状态 | 避免上线后出现空字段导致提现判断异常 |
| 前台兼容 | 前台提现页展示的手续费、到账数量、最小/最大限制必须取新配置 | 后管规则必须与用户看到的规则一致 |
| 接口兼容 | 现有字段如果仍被旧流程消费，需要保留读取兼容直到前后端完成切换 | 降低发布风险 |

## 6. 验收标准

| 场景 | Given | When | Then |
|-----|-------|------|------|
| 新增币账户 | 运营进入币账户管理 | 点击新增币账户并填写提现手续费、数量上下限、USDT 金额上下限 | 系统保存成功，列表和详情展示一致 |
| 字段校验 | 最小提现数量大于最大提现数量 | 点击保存 | 系统阻止保存，并提示「最小提现数量不能大于最大提现数量」 |
| 会员折扣 | 币账户手续费为 10 USDT，会员折扣比例为 80% | 用户发起提现 | 实际手续费为 8 USDT，不按 20% 或固定 80 USDT 计算 |
| 免手续费 | 会员折扣比例为 0% | 用户发起提现 | 实际手续费为 0，到账数量不扣除手续费 |
| 不减免 | 会员折扣比例为 100% | 用户发起提现 | 实际手续费等于币账户基础提现手续费 |
| 额度限制 | 提现数量满足币本位限制但折算金额超过最大提现金额 | 用户提交提现 | 系统拒绝并展示 USDT 金额上限提示 |
| 日志 | 运营修改提现手续费或折扣比例 | 保存成功 | 操作日志可查看变更前后值 |

## 7. 风险与待确认

| 问题 | Owner | 建议处理 | 开发前是否必须关闭 |
|-----|-------|---------|----------------|
| USDT 折算价格取哪个价格源、哪个时点 | 产品 + 后端 | 建议取提现提交时服务端可用的统一估值价格，并在日志记录价格 | 是 |
| 法币提现手续费的单位是否永远是币种数量 | 产品 + 财务 | 若法币账户本身以 USD/EUR 等计价，需要确认手续费单位显示规则 | 是 |
| 历史会员折扣字段是否已有错误数据 | 后端 + 运营 | 上线前导出当前配置，确认是否需要批量迁移或人工修正 | 是 |
| 最大提现数量缺省值如何设置 | 产品 + 风控 | 不能默认无限大，建议按币种风险等级给默认值 | 是 |
| 前台错误提示是否多语言同步 | 产品 + 前端 | 涉及提现提示的文案需进入国际化管理 | 是 |

> 建议在开发前先关闭价格源和历史数据迁移两个问题。它们不只是实现细节，会直接影响用户实际扣费和提现是否被错误拦截。
