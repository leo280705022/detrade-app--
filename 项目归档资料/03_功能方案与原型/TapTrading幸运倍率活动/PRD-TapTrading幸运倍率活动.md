# TapTrading 幸运倍率活动 PRD

> 版本：v2.3 | 日期：2026-07-30 | 状态：待评审

---

## 1. 需求背景

TapTrading 是平台核心互动玩法之一，用户通过在 K 线图表区域点击下单，根据 K 线走势是否经过所选倍率方块来决定盈亏。为提升用户参与度和日活，计划推出**幸运倍率活动**，通过每日公开/隐藏特殊倍率的方式，增加游戏趣味性和社交传播性。

## 2. 活动目标

| 指标 | 目标值 |
|------|--------|
| 日参与用户数提升 | +30% |
| TapTrading 日均投注笔数提升 | +20% |
| TG 频道互动率提升 | +50% |
| 新用户通过活动转化 | +15% |

## 3. 活动规则设计

### 3.1 Lucky Multiplier（公开幸运倍率）— 每日区间值

- 每日由管理员配置一个 **倍率区间**（如 150x ~ 250x），**每天可设置不同的区间范围和奖励金额**
- 用户投注的倍率方块如果落在该 Lucky 区间内，且 K 线路径经过该方块，则获得 Lucky 奖励
- 奖励类型：真金/奖励金/优惠券（后管按日配置），选优惠券时无奖励金额
- 中奖人数不限，所有命中区间内倍率的用户均可获得奖励
- **Hidden 倍率不会出现在当日 Lucky 区间内**，确保两类奖励互斥
- 每日 00:00 UTC 重置，管理员在 TG 频道公布当日 Lucky 倍率区间
- 奖励发放：系统自动发放至用户 Bonus 账户
- 活动周期：长期活动，后管可配置起止日期

### 3.2 Hidden Multiplier（隐藏神秘倍率）

| 项目 | 说明 |
|------|------|
| 倍率生成 | 每日 00:00 UTC 由管理员手动配置一个隐藏倍率（2x~9999x），配置时系统实时校验是否与 Lucky 区间冲突，冲突则禁止保存 |
| 中奖条件 | 用户投注该倍率，且 K 线走势经过该倍率方块 |
| 名额限制 | 仅限前 5 名命中者 |
| 奖励金额 | 100U（后管可配置奖励类型：真金/奖励金/优惠券） |
| 奖励发放 | 系统自动发放至用户 Bonus 账户 |
| 公示方式 | 系统自动公示：若 12:00 UTC 前已有用户命中，前端立即展示 Hidden 倍率值；若 12:00 UTC 仍无人命中，系统自动公布倍率值 |

**Hidden 倍率公示逻辑：**
1. Hidden 倍率在被触发或系统公布前，对所有用户保持隐藏（前端不展示具体数值）
2. **提前命中公示**：若有用户在 12:00 UTC 前命中 Hidden 倍率，前端立即公示该 Hidden 倍率值（如「Today's Hidden Multiplier: 347x — Revealed!」），所有用户可在前端看到
3. **定时自动公示**：若到达 12:00 UTC 仍无人命中，系统自动在前端公布当日 Hidden 倍率值
4. 公示后 TG Bot 频道同步推送中奖/揭晓消息

### 3.3 活动限制

| 限制项 | 规则 |
|--------|------|
| 参与门槛 | 需完成 KYC 认证 |
| 最低投注 | 0.1U（与 TapTrading 最低投注一致） |
| 奖励限制 | 无单日奖励次数上限。同一用户对同一倍率方块的多次投注，命中时仅首次获得 Lucky 奖励、首次获得 Hidden 奖励（即同一倍率方块 Lucky 和 Hidden 各只奖励一次） |
| 防刷机制 | 同一设备/IP 多账号视为异常，取消奖励资格 |
| 奖励到账 | Bonus 余额，需满足 wagering 要求后方可提现 |

## 5. 后管设计

> 菜单路径：活动管理 > 幸运倍率活动（从 TapTrading 管理迁移至活动管理）
> 页面结构：活动列表页 → 新建活动页 / 活动详情页（内部通过 Tab 切换 5 个功能模块）

### 5.0 活动列表页

- **筛选条件**：活动状态（全部/进行中/已结束）+ 上架状态（全部/待上架/已上架/已下架）+ 日期范围 + 活动名称搜索
- **列表字段**：序号、活动名称、活动状态、上架状态、活动周期、参与人数、奖励发放、创建时间、操作
- **操作按钮**（按有效状态组合列出）：
  - 进行中 + 已上架：管理、查看、**下架**
  - 进行中 + 待上架：管理、**上架**（若已有其他活动已上架，弹出冲突提示，需先下架当前活动）
  - 进行中 + 已下架：**上架**、查看
  - 已暂停 + 已上架：管理、查看、**下架**、**编辑配置**
  - 已暂停 + 待上架：管理、**上架**、**编辑配置**
  - 已结束 + 已下架：查看、**复制为新活动**
- **上架约束**：全局同一时间只允许 **1 个活动** 处于「已上架」状态。上架新活动时，若已有活动在线，系统弹出冲突确认弹窗，展示当前已上架活动信息，运营确认后自动下架原活动并上架新活动
- **新建活动**：点击「+ 新建活动」进入新建活动向导页

#### 活动状态模型

活动状态与上架状态是**两个独立维度**，暂停/开启活动不影响上架状态，但活动结束时系统自动触发下架。

| 维度 | 状态 | 说明 |
|------|------|------|
| 活动状态 | 进行中 | 活动周期内，可暂停/开启 |
| 活动状态 | 已暂停 | 运营主动暂停，可恢复为进行中 |
| 活动状态 | 已结束 | 活动到期或手动结束，不可编辑，仅支持「复制为新活动」 |
| 上架状态 | 待上架 | 活动已创建但未上架，业务端不展示 |
| 上架状态 | 已上架 | 业务端正常展示，全局仅允许 1 个 |
| 上架状态 | 已下架 | 活动结束自动下架，或运营手动下架 |

**有效状态组合（6 种）：**

| 组合 | 活动状态 | 上架状态 | 说明 |
|------|----------|----------|------|
| ① | 进行中 | 已上架 | 正常运行中，业务端可见 |
| ② | 进行中 | 待上架 | 已创建未上架，等待运营操作 |
| ③ | 进行中 | 已下架 | 运营主动下架运行中的活动（临时下线） |
| ④ | 已暂停 | 已上架 | 暂停但仍在业务端展示 |
| ⑤ | 已暂停 | 待上架 | 暂停且未上架 |
| ⑥ | 已结束 | 已下架 | 活动结束，系统自动下架（唯一有效组合） |

**无效组合**：已结束 + 已上架、已结束 + 待上架（活动结束时系统自动下架，不存在其他上架状态）

**状态转换规则**：
- 暂停/开启活动：**不改变上架状态**（如「进行中 + 已上架」暂停后变为「已暂停 + 已上架」）
- 活动结束：自动将上架状态设为「已下架」
- 手动下架：运营可随时下架「已上架」状态的活动（无论活动是进行中还是已暂停）
- 手动上架：仅「待上架」状态支持手动上架，需满足全局唯一约束

#### 新建活动流程（3 步向导）

1. **基础信息**：活动名称、起止时间、最小下单金额、**立即上架开关**
   - 开启「立即上架」：到达开始时间后自动上架并开始
   - 未开启：创建后处于「待上架」状态，需到活动列表手动上架
2. **倍率配置**：Lucky 每日区间配置 + Hidden 每日倍率配置
   - Lucky：按日配置区间下限/上限 + 奖励类型 + 奖励金额，支持随机生成
   - Hidden：按日配置倍率 + 奖励类型 + 奖励金额，实时校验与当日 Lucky 区间冲突
3. **活动内容配置**：Banner 文案、中奖弹窗、TG 推送模板、推送开关

### 5.1 活动概览 Tab

- 活动状态栏（运行中/已暂停/已结束）+ **暂停/开启活动切换按钮** + **编辑配置按钮**（暂停状态或待上架状态时显示，点击后跳转至倍率配置 Tab 进行编辑，不弹出独立编辑弹窗）
- **活动基础信息编辑区**（暂停状态或待上架状态时可编辑）：
  - 活动名称：可修改
  - 活动时间：开始时间不可修改，结束时间可修改（必须大于当前时间）
  - 最小下单金额：可修改
- 今日数据统计：参与人数、Lucky 中奖人数、Hidden 中奖人数（3 卡片）
- **今日 Lucky 倍率区间卡片**：展示当日 Lucky 区间（如 150x ~ 250x）、投注次数、命中率、中奖人数和奖励发放
  - **命中率计算规则**：命中率 = 今日 Lucky 中奖次数 ÷ 今日投注该 Lucky 区间内倍率方块的总投注次数 × 100%。分母为投注了 Lucky 区间内任意倍率方块的总次数，分子为其中实际命中并获得 Lucky 奖励的次数
- **今日 Hidden Multiplier 卡片**：展示隐藏状态（???）、自动公示倒计时
  - **自动公示倒计时规则**：倒计时目标为当日 12:00 UTC。若 12:00 UTC 前已有用户命中 Hidden 倍率，倒计时立即停止并替换为「已公示」状态，展示实际 Hidden 倍率值和中奖用户信息；若到达 12:00 UTC 仍无人命中，系统自动公示倍率值，倒计时同步消失
- **最近中奖记录**：仅展示最近 5 条中奖记录，按时间倒序排列。点击「查看全部」跳转至中奖记录 Tab

#### 活动状态与编辑权限矩阵

编辑权限由**活动状态**和**上架状态**两个维度共同决定：

**活动状态维度 — 配置项编辑权限：**

| 配置项 | 进行中 | 已暂停 | 已结束 |
|--------|--------|--------|--------|
| 活动名称 | 不可编辑 | 可编辑 | 不可编辑 |
| 起止日期 | 不可编辑 | 可编辑 | 不可编辑 |
| 最小下单金额 | 不可编辑 | 可编辑 | 不可编辑 |
| Lucky 倍率区间 | 可编辑（仅当日，活动概览卡片修改） | 可编辑 | 不可编辑 |
| Lucky 奖励类型/金额 | 可编辑（仅当日，活动概览卡片修改） | 可编辑 | 不可编辑 |
| Hidden 奖励类型/金额（按天） | 不可编辑（当日已生效） | 可编辑 | 不可编辑 |
| Hidden 倍率（未来日期） | 可编辑 | 可编辑 | 不可编辑 |
| Hidden 倍率（已过去日期） | 不可编辑 | 不可编辑 | 不可编辑 |
| 活动内容文案 | 可编辑 | 可编辑 | 不可编辑 |
| TG 推送开关 | 可编辑 | 可编辑 | 不可编辑 |

**上架状态维度 — 补充规则：**

| 上架状态 | 补充规则 |
|----------|----------|
| 待上架 | 活动未对用户展示，**所有配置项均可编辑**（覆盖上方活动状态限制，如活动名称、起止日期等也可修改） |
| 已上架 | 按上方活动状态维度的权限执行 |
| 已下架 | 按上方活动状态维度的权限执行 |

**各组合可用操作：**

| 状态组合 | 可用操作 |
|----------|----------|
| 进行中 + 已上架 | 暂停活动、下架、管理、查看 |
| 进行中 + 待上架 | 上架、暂停活动、管理 |
| 进行中 + 已下架 | 上架、查看 |
| 已暂停 + 已上架 | 开启活动、下架、编辑配置、管理、查看 |
| 已暂停 + 待上架 | 开启活动、上架、编辑配置、管理 |
| 已结束 + 已下架 | 复制为新活动、查看（唯一有效组合，全部只读） |

**设计原则**：
- **待上架 = 全量编辑**：活动未对用户展示，运营可自由修改任何配置，包括基础信息
- **运行中 + 已上架 = 最小范围编辑**：仅允许通过活动概览卡片调整当日 Lucky 倍率区间和奖励（保留灵活性，一般运营不会操作）。涉及 Hidden 奖励金额、Lucky 批量修改等，需先暂停活动后在倍率配置 Tab 中操作
- **暂停 = 全面编辑**：活动暂停后解锁所有配置项的编辑权限
- **手动下架不影响活动状态**：下架运行中的活动后变为「进行中 + 已下架」，下架暂停中的活动后变为「已暂停 + 已下架」

**已结束活动重启流程**：已结束的活动不可直接重新开启（避免历史数据混乱）。运营需通过「复制为新活动」功能，基于原活动配置创建新活动实例，可修改名称和起止日期，选择是否开启「立即上架」。原活动保持已结束状态，所有历史数据保留。

**新建活动上架逻辑**：
- 创建活动时可选择「立即上架」开关
- 开启：到达活动开始时间后系统自动上架，活动自动开始；若此时已有其他活动处于「已上架」状态，系统将不会自动上架，需运营手动到活动列表处理冲突
- 未开启：活动创建后处于「待上架」状态，需运营到活动列表手动操作上架
- 无论是否开启，活动创建后均可在倍率配置 Tab 中提前配置好所有数据
- **全局约束**：同一时间只允许 1 个活动处于「已上架」状态，上架新活动前需确保无其他在线活动

### 5.2 倍率配置 Tab

- **Lucky 倍率每日配置**：以日期表格形式一次性配置活动周期内每天的 Lucky 区间和奖励
  - 每行包含：日期、区间下限、区间上限、奖励类型（真金/奖励金/优惠券）、奖励金额
  - 当选择「优惠券」时，提供下拉选择已配置的优惠券（来自「活动管理 > 优惠券配置」），此时无奖励金额输入
  - 支持单行随机生成区间 + 一键随机全部未配置天数
  - 校验规则：区间下限必须小于上限，下限最小为 2x
  - 已过日期（今天及之前）的配置不可修改，显示为「已生效」
  - 修改未来日期的 Lucky 区间后，Hidden 倍率需重新校验是否与新区间冲突
- **Hidden Multiplier 配置**：以日期表格形式一次性配置活动周期内每天的 Hidden 倍率
  - 每行包含：日期、Hidden 倍率、奖励类型（真金/奖励金/优惠券）、奖励金额
  - 支持手动输入或单行/一键随机生成，输入时实时校验是否与**当日** Lucky 区间冲突（冲突行标红）
  - 每日名额为全局统一配置

### 5.3 活动内容配置 Tab

- 业务端所有文案的模板配置（默认语言 English）
- **多语言文案通过系统「国际化管理 > 语言配置」模块维护**，不在本页面配置中文
- Banner 标题/副标题/规则摘要
- TG Bot 推送模板（Lucky 公布/Hidden 揭晓/Hidden 自动公示）
- Lucky/Hidden 中奖弹窗文案由前端按设计稿写死，不在后管配置

### 5.4 中奖记录 Tab

- 中奖记录列表（筛选：日期、类型、用户、状态）
- 奖励发放状态 + 奖励类型展示

## 7. 风控方案

### 7.1 防刷策略

| 策略 | 说明 |
|------|------|
| 设备指纹 | 同一设备多账号参与，标记异常 |
| IP 限制 | 同一 IP 多账号，限制奖励发放 |
| 行为分析 | 短时间内高频投注同一倍率，触发风控 |
| KYC 要求 | 必须完成 KYC 才能参与活动和领取奖励 |
| 投注验证 | 奖励发放前验证投注记录真实性 |

### 7.2 异常处理

| 场景 | 处理方式 |
|------|----------|
| 奖励发放失败 | 自动重试 3 次，失败后转人工处理 |
| 用户投诉未到账 | 后管手动补发，记录操作日志 |
| 系统异常导致多发放 | 冻结异常账户，人工审核 |
| Hidden 倍率泄露 | 立即更换当日 Hidden 倍率，记录安全事件 |
| Lucky 区间与 Hidden 冲突 | Hidden 倍率生成时自动排除 Lucky 区间，若区间配置变更导致冲突则提示运营调整 |

## 8. 技术要点

### 8.1 倍率生成与存储
- 每日 00:00 UTC 定时任务生成当日 Lucky/Hidden 倍率
- 倍率数据存储在独立的活动配置表中
- Lucky Multiplier 为区间值（如 150x~250x），业务端需展示区间而非单一值，服务端判定用户投注倍率是否落在区间内
- Hidden Multiplier 绝对不能泄露到业务端，只在服务端判定；生成时自动排除 Lucky 区间

### 8.2 中奖判定逻辑
```
1. 用户点击倍率方块下注
2. K 线动画播放完成，确定实际路径
3. 检查用户投注倍率是否在 K 线路径上
4. 如果在路径上，检查该用户是否已在此倍率方块获得过 Lucky 奖励 → 若已获得则跳过，不再重复发放
5. 如果在路径上且未重复，检查投注倍率是否落在 Lucky 区间内（如 150x~250x）→ 发放 Lucky 奖励，标记该用户在此方块已中奖
6. 如果在路径上，检查该用户是否已在此倍率方块获得过 Hidden 奖励 → 若已获得则跳过，不再重复发放
7. 如果在路径上且未重复，检查是否为 Hidden Multiplier → 检查名额 → 发放 Hidden 奖励，标记该用户在此方块已中奖
8. 记录中奖信息，更新 Hidden 已中奖计数
```

> **去重规则**：同一用户对同一倍率方块的多次投注，命中时 Lucky 和 Hidden 各只奖励一次。无单日总奖励次数上限，用户可在不同倍率方块分别获得奖励。

### 8.3 并发处理
- Hidden Multiplier 名额限制需使用分布式锁
- 中奖判定与奖励发放使用消息队列异步处理
- Hidden 倍率自动公示使用定时任务触发（12:00 UTC 检查并公布）
