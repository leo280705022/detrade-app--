# TapTrading 幸运倍率活动 PRD

> 版本：v2.1 | 日期：2026-07-22 | 状态：待评审

---

## 1. 需求背景

TapTrading 是平台核心互动玩法之一，用户通过在 K 线图表区域点击下单，根据 K 线走势是否经过所选倍率方块来决定盈亏。为提升用户参与度和日活，计划推出**幸运倍率活动**，通过每日公开/隐藏特殊倍率的方式，增加游戏趣味性和社交传播性。

## 2. 活动目标

| 指标 | 目标值 |
|------|--------|
| 日参与用户数提升 | +30% |
| TapTrading 日均投注笔数提升 | +20% |
| TG 频道互动率提升 | +50% |
| 新用户通过活动转化 | +15% |

## 3. 活动规则设计

### 3.1 Lucky Multiplier（公开幸运倍率）— 区间值

- 每日由管理员设置一个 **倍率区间**（如 150x ~ 250x），而非单一倍率值
- 用户投注的倍率方块如果落在该 Lucky 区间内，且 K 线路径经过该方块，则获得 Lucky 奖励
- 奖励：固定 20U（后管可配置奖励类型：真金/奖励金/优惠券）
- 中奖人数不限，所有命中区间内倍率的用户均可获得奖励
- **Hidden 倍率不会出现在 Lucky 区间内**，确保两类奖励互斥
- 每日 00:00 UTC 重置，管理员在 TG 频道公布当日 Lucky 倍率区间
- 奖励发放：系统自动发放至用户 Bonus 账户
- 活动周期：长期活动，后管可配置起止日期

### 3.2 Hidden Multiplier（隐藏神秘倍率）

| 项目 | 说明 |
|------|------|
| 倍率生成 | 每日 00:00 UTC 由系统随机生成一个隐藏倍率（2x~9999x，自动排除 Lucky 区间），管理员不可见/不可修改 |
| 中奖条件 | 用户投注该倍率，且 K 线走势经过该倍率方块 |
| 名额限制 | 仅限前 5 名命中者 |
| 奖励金额 | 100U（后管可配置奖励类型：真金/奖励金/优惠券） |
| 保底机制 | 若当日 12:00 UTC 前无人命中，系统/人工指定首个中奖者 |
| 奖励发放 | 系统自动发放至用户 Bonus 账户 |
| 公示方式 | TG Bot 频道实时推送中奖消息 |

**保底机制详细说明：**
1. 每日 12:00 UTC 系统检查 Hidden Multiplier 是否已有中奖者
2. 若无人命中，后管运营人员可手动指定一名当日参与过 TapTrading 的用户作为中奖者（需先验证 UID 是否存在，候选池仅支持单选）
3. 若运营未操作，系统自动从当日参与用户中随机抽取一名
4. 保底中奖者同样获得 100U 奖励，TG 频道正常推送
5. **保底配置当日锁定**：保存后当日不可再修改，次日 00:00 UTC 自动解锁
6. **名额满后禁用**：已中奖名额满足后，不再支持手动指定中奖

### 3.3 活动限制

| 限制项 | 规则 |
|--------|------|
| 参与门槛 | 需完成 KYC 认证 |
| 最低投注 | 0.1U（与 TapTrading 最低投注一致） |
| 单日上限 | 每用户每日 Lucky 奖励上限 1 次，Hidden 奖励上限 1 次 |
| 防刷机制 | 同一设备/IP 多账号视为异常，取消奖励资格 |
| 奖励到账 | Bonus 余额，需满足 wagering 要求后方可提现 |

## 4. 业务端设计

### 4.1 Web 端

#### 4.1.1 活动入口
- TapTrading 页面顶部 Activity Banner，点击展开活动详情面板
- Banner 内容：「🍀 Today's Lucky Range: 150x ~ 250x | 🔒 Secret Multiplier Hidden!」

#### 4.1.2 倍率展示区
- 在现有倍率网格中，Lucky 区间内的所有倍率方块增加**金色边框 + 闪烁动画**（如 150x~250x 区间内的方块全部高亮）
- Hidden Multiplier 对应方块**不做特殊标记**（保持神秘感，不暴露哪个是 Hidden）
- 倍率网格上方增加活动信息条：显示今日 Lucky 倍率区间、Hidden 剩余名额

#### 4.1.3 中奖弹窗
- **Lucky 命中**：金色主题弹窗
  - 标题：「 Lucky Multiplier Hit!」
  - 内容：「You hit the Lucky Multiplier 188x (within 150x~250x range)!」
  - 奖励：「+20U Bonus」
  - 按钮：「Claim Reward」→「Awesome!」
- **Hidden 命中**：紫色主题弹窗（更炫酷）
  - 标题：「🔮 Secret Multiplier Hit!」
  - 内容：「You discovered the hidden multiplier 347x!」
  - 奖励：「+100U Bonus」
  - 特效：全屏粒子动画 + 音效
  - 按钮：「Claim Reward」→「Incredible!」

#### 4.1.4 活动规则面板
- 右侧边栏或底部抽屉展示完整活动规则
- 包含：活动说明、奖励规则、发放规则、FAQ

### 4.2 H5 端（Telegram Mini App）

#### 4.2.1 设计适配
- 采用 Telegram Mini App 设计规范
- 活动 Banner 置于页面顶部，高度适配 TG 安全区域
- 倍率网格适配小屏幕，采用 3 列或 4 列布局
- 中奖弹窗采用 TG 原生弹窗风格

#### 4.2.2 特殊交互
- 支持 TG 分享按钮：「Share my win!」→ 生成分享卡片
- 分享卡片内容：「I just hit the Lucky Multiplier in the 150x~250x range on DeTrade! 🍀」

### 4.3 App 端

#### 4.3.1 设计适配
- 与 Web 端保持一致的视觉风格
- 倍率网格支持横屏/竖屏自适应
- 中奖弹窗支持 Haptic Feedback（震动反馈）
- 支持 Push Notification 推送活动提醒

#### 4.3.2 推送策略
| 推送类型 | 触发时机 | 内容 |
|----------|----------|------|
| 活动开始 | 每日 00:00 用户本地时间 | 「Today's Lucky Range: 150x~250x is live!」 |
| 倍率提醒 | 用户 2 小时未参与 | 「Don't miss today's Lucky Range!」 |
| 中奖通知 | 命中时 | 「Congratulations! You hit the Lucky Multiplier!」 |

## 5. 后管设计

> 菜单路径：活动管理 > 幸运倍率活动（从 TapTrading 管理迁移至活动管理）
> 页面结构：单一页面，内部通过 Tab 切换 6 个功能模块

### 5.1 活动概览 Tab

- 活动状态栏（运行中/已暂停/已结束）+ **暂停/开启活动切换按钮** + 编辑按钮
- 今日数据统计：参与人数、Lucky 中奖人数、Hidden 中奖人数（3 卡片）
- 今日 Lucky 倍率区间展示（如 150x ~ 250x，可修改区间）
- 今日 Hidden Multiplier 展示（隐藏状态，显示保底倒计时）
- 最近中奖记录列表

### 5.2 倍率配置 Tab

- **Lucky 区间配置**：设置区间下限/上限 + **奖励类型（真金/奖励金/优惠券）** + 奖励金额
  - 当选择「优惠券」时，提供下拉选择已配置的优惠券（来自「活动管理 > 优惠券配置」）
- **Hidden Multiplier 配置**：随机范围（自动排除 Lucky 区间）、每日名额、**奖励类型（真金/奖励金/优惠券）** + 奖励金额

### 5.3 活动内容配置 Tab

- 业务端所有文案的模板配置（默认语言 English）
- **多语言文案通过系统「国际化管理 > 语言配置」模块维护**，不在本页面配置中文
- Banner 标题/副标题/规则摘要
- Lucky/Hidden 中奖弹窗文案（含变量：{multiplier}、{reward}、{rangeMin}、{rangeMax}）
- TG Bot 推送模板（Lucky 公布/Hidden 揭晓/保底触发）

### 5.4 中奖记录 Tab

- 中奖记录列表（筛选：日期、类型、用户、状态）
- 奖励发放状态 + 奖励类型展示
- **详情弹窗**：点击「详情」展示完整中奖信息（中奖时间、用户、类型、倍率、区间、投注金额、奖励金额、奖励类型、发放状态、交易对、订单 ID、操作日志）
- **手动补发功能**：点击「手动发放」弹出二次确认弹窗，展示用户信息、奖励金额等，确认后发放

### 5.5 保底管理 Tab

- 保底机制开关 + 截止时间配置
- 触发条件配置（名额未满 / 无人命中）
- **当日配置锁定**：保底配置保存后当日不可再修改，次日 00:00 UTC 后自动解锁
- **保底操作流程**：
  - 自动保底：截止时间到达后系统从候选池随机抽取
  - 手动保底：运营可手动指定中奖者（输入用户 ID 需先**验证用户是否存在**，或从候选池**单选**一名用户）
  - 混合模式：先手动指定部分名额，剩余由系统自动抽取
  - **名额满后禁用**：已中奖名额满足后，不再支持手动指定中奖
- 今日保底状态：Hidden 倍率、已中奖/总名额、剩余名额、倒计时、候选池人数
- 操作按钮：
  - 手动指定中奖者（弹窗）
  - 手动触发保底开奖（**二次确认弹窗**，展示 Hidden 倍率、剩余名额、候选池人数）
  - 查看候选池

### 5.6 数据统计 Tab

- 累计统计：参与人数、奖励发放、Lucky/Hidden 中奖人次（4 卡片）
- 每日数据明细表（参与人数、Lucky/Hidden 中奖、奖励发放、保底触发）
- 数据导出功能

### 5.7 关联页面（保留在 TapTrading 管理下）

- TapTrading 基础配置：玩法开关、最小下单金额、最高投注金额、单期时长等
- TapTrading 交易对管理：交易对上下线、投注数据

## 7. 风控方案

### 7.1 防刷策略

| 策略 | 说明 |
|------|------|
| 设备指纹 | 同一设备多账号参与，标记异常 |
| IP 限制 | 同一 IP 多账号，限制奖励发放 |
| 行为分析 | 短时间内高频投注同一倍率，触发风控 |
| KYC 要求 | 必须完成 KYC 才能参与活动和领取奖励 |
| 投注验证 | 奖励发放前验证投注记录真实性 |

### 7.2 异常处理

| 场景 | 处理方式 |
|------|----------|
| 奖励发放失败 | 自动重试 3 次，失败后转人工处理 |
| 用户投诉未到账 | 后管手动补发，记录操作日志 |
| 系统异常导致多发放 | 冻结异常账户，人工审核 |
| Hidden 倍率泄露 | 立即更换当日 Hidden 倍率，记录安全事件 |
| Lucky 区间与 Hidden 冲突 | Hidden 倍率生成时自动排除 Lucky 区间，若区间配置变更导致冲突则提示运营调整 |

## 8. 技术要点

### 8.1 倍率生成与存储
- 每日 00:00 UTC 定时任务生成当日 Lucky/Hidden 倍率
- 倍率数据存储在独立的活动配置表中
- Lucky Multiplier 为区间值（如 150x~250x），业务端需展示区间而非单一值，服务端判定用户投注倍率是否落在区间内
- Hidden Multiplier 绝对不能泄露到业务端，只在服务端判定；生成时自动排除 Lucky 区间

### 8.2 中奖判定逻辑
```
1. 用户点击倍率方块下注
2. K 线动画播放完成，确定实际路径
3. 检查用户投注倍率是否在 K 线路径上
4. 如果在路径上，检查投注倍率是否落在 Lucky 区间内（如 150x~250x）→ 发放 20U
5. 如果在路径上，检查是否为 Hidden Multiplier → 检查名额 → 发放 100U
6. 记录中奖信息，更新 Hidden 已中奖计数
```

### 8.3 并发处理
- Hidden Multiplier 名额限制需使用分布式锁
- 中奖判定与奖励发放使用消息队列异步处理
- 保底机制使用定时任务 + 人工操作双保险
