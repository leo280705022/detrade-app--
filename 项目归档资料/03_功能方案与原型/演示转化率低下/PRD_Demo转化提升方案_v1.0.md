## 一、需求背景

### 1.1 业务现状

DeTrade 平台当前面临严重的转化率问题：

| 指标         | 当前值               | 行业基准     | 差距         |
| ---------- | ----------------- | -------- | ---------- |
| 注册转化率      | 0.22% (42/19,233) | 2%\~5%   | 低 10\~20 倍 |
| Demo→注册转化率 | 0.36% (42/11,771) | 10%\~20% | 低 30\~50 倍 |
| 首充转化率      | <5%               | 30%\~40% | 低 6\~8 倍   |
| 7 日留存率     | <10%              | 40%\~50% | 低 4\~5 倍   |

### 1.2 Demo 用户数据分析

**Demo 用户总量**：11,771 人

**余额分布**：

- 余额 >500（深度消耗）：4,622 人（39.3%）
- 余额 =500（零消耗）：425 人（3.6%）
- 余额 300\~500（轻度消耗）：6,683 人（56.8%）
- 余额 100\~300（中度消耗）：5 人（0.04%）
- 余额 0\~100（几乎用完）：36 人（0.3%）

**关键发现**：

1. **56.8% 的用户浅尝辄止**（余额在 300\~500 之间），说明用户进来后没有深度体验就被流失了
2. **39.3% 的用户深度消耗**（>500），说明产品本身对这部分用户有吸引力，但从 Demo → 注册的转化几乎为零
3. **425 人完全未消耗**（余额 = 500），说明注册后根本没有进入交易页面

### 1.3 核心问题诊断

1. **Demo 交易中无注册触发点**：用户可以无限期使用 Demo 而无需注册
2. **入金激励不足**："首充翻倍最多$100"吸引力弱，缺乏阶梯式奖励
3. **无新手引导系统**：用户不知道下一步该做什么，缺乏继续探索的动力
4. **缺乏从 Demo 到真实的过渡**：没有"Demo 盈利变现"的引导机制

## 八、风险与应对

### 8.1 技术风险

| 风险       | 影响      | 应对措施                  |
| -------- | ------- | --------------------- |
| 弹窗触发逻辑冲突 | 用户体验差   | 实现触发频率控制，每次会话最多 3 个弹窗 |
| 数据同步延迟   | 触发时机不准确 | 使用实时数据流，确保数据一致性       |
| 弹窗加载慢    | 用户流失    | 预加载弹窗资源，优化加载性能        |

### 8.2 业务风险

| 风险        | 影响         | 应对措施            |
| --------- | ---------- | --------------- |
| 弹窗过度打扰    | 用户反感，流失率上升 | A/B 测试优化弹窗频率和内容 |
| 入金激励成本过高  | 平台亏损       | 设置奖金上限，动态调整奖励比例 |
| 新手任务完成率过低 | 留存效果不佳     | 优化任务难度和奖励机制     |

### 8.3 合规风险

| 风险           | 影响   | 应对措施                  |
| ------------ | ---- | --------------------- |
| 入金激励涉嫌赌博     | 法律风险 | 咨询法律顾问，确保合规           |
| Demo 资金机制不透明 | 用户投诉 | 明确说明 Demo 资金规则，提供 FAQ |
