# DeTrade 用户分层设计方案 v1.0

## 1. 方案概述

### 1.1 设计目标
- **精准识别**：通过多维度数据分析，准确识别用户价值层级
- **差异化运营**：针对不同层级用户推送定制化福利与活动
- **提升LTV**：通过分层激励提升用户生命周期价值
- **风险控制**：识别并隔离羊毛党、套利用户

### 1.2 核心原则
- **数据驱动**：所有分层判定基于客观数据指标
- **动态调整**：用户层级每日/每周自动更新
- **正向激励**：高价值用户获得更多权益，低质用户限制权益
- **财务可控**：所有福利发放严格控制在利润范围内

## 2. 用户分层模型

### 2.1 分层架构（6层模型）

| 层级 | 名称 | 用户画像 | 占比预估 | 核心价值 |
|------|------|----------|----------|----------|
| **SS** | 超级鲸鱼 | 超高净值、超高贡献、平台核心用户 | < 1% | 贡献 30%+ 平台利润 |
| **S** | 鲸鱼用户 | 高净值、高贡献、高忠诚 | 1-3% | 贡献 25%+ 平台利润 |
| **A** | 主力用户 | 稳定交易、稳定入金、未来增长点 | 10-15% | 贡献 35%+ 平台利润 |
| **B** | 散户用户 | 高频小额、情绪化交易、易流失 | 30-40% | 活跃基础、转化潜力 |
| **C** | 新手用户 | 刚注册、未充值或小额体验 | 30-40% | 需要引导转化 |
| **R** | 风险用户 | 羊毛党、套利者、快进快出 | 5-10% | 需严格风控限制 |

### 2.2 分层判定指标

#### 2.2.1 核心维度定义

**维度一：资产价值 (Asset Value) - 权重 30%**
| 指标 | 说明 | 数据来源 |
|------|------|----------|
| 账户净资产 (AUM) | 钱包余额 + 未结盈亏 | 钱包系统 |
| 净入金 | 累计充值 - 累计提现 | 支付系统 |
| 资金留存率 | 资金在账户平均停留天数 | 支付+风控系统 |

**维度二：交易贡献 (Trading Contribution) - 权重 35%**
| 指标 | 说明 | 数据来源 |
|------|------|----------|
| 手续费贡献 | 累计交易手续费 + 资金费率 | 撮合/结算系统 |
| 交易频次 | 日均/周均开仓次数 | 订单系统 |
| 交易量 | 30日累计交易量 | 订单系统 |
| 产品覆盖度 | 使用功能种类数 | 各业务模块 |

**维度三：活跃度 (Engagement) - 权重 20%**
| 指标 | 说明 | 数据来源 |
|------|------|----------|
| 活跃天数 | 过去30天登录并有操作天数 | 行为日志 |
| DAU/MAU | 日活/月活比例 | 行为日志 |
| 功能渗透率 | 使用核心功能比例 | 各业务模块 |

**维度四：用户质量 (User Quality) - 权重 15%**
| 指标 | 说明 | 数据来源 |
|------|------|----------|
| 薅羊毛指数 | 赠金收益 / 自有资金收益 | 风控/营销系统 |
| 资金停留时间 | 充提时间差 | 支付/风控系统 |
| 设备关联数 | 同设备登录账号数 | 安全/指纹系统 |
| KYC状态 | 实名认证等级 | KYC系统 |

#### 2.2.2 层级判定标准

```
【SS级 - 超级鲸鱼】
必须满足：
- 账户净资产 ≥ 200,000 USDT
- 月手续费贡献 ≥ 5,000 USDT
- 过去30天活跃天数 ≥ 20天
- 无风险标签

【S级 - 鲸鱼用户】
必须满足：
- 账户净资产 ≥ 50,000 USDT
- 月手续费贡献 ≥ 1,000 USDT
- 过去30天活跃天数 ≥ 15天
- 无风险标签

【A级 - 主力用户】
必须满足：
- 账户净资产 ≥ 5,000 USDT
- 周交易频次 ≥ 5次
- 过去30天活跃天数 ≥ 10天
- 累计充值 ≥ 1,000 USDT
- 无风险标签

【B级 - 散户用户】
满足以下任一：
- 账户净资产 < 5,000 USDT 且 有交易行为
- 平均杠杆 > 20x
- 爆仓次数 > 1
- 体验金消耗占比 > 50%
- 无风险标签

【C级 - 新手用户】
满足以下全部：
- 注册时间 < 30天
- 账户净资产 < 1,000 USDT
- 累计充值 < 500 USDT
- 无风险标签

【R级 - 风险用户】
满足以下任一即标记：
- 薅羊毛指数 > 3 (赠金收益/自有资金收益)
- 资金停留时间 < 10分钟
- 设备关联账号 > 3
- 快进快出次数 > 3
- 仅交易赠金无充值
```

## 3. 差异化福利体系

## 4. 分层运营策略

### 4.1 生命周期运营

```
【引入期】C级 → B级
目标：完成首充、首单交易
策略：
- 首充翻倍激励
- 新手任务引导
- 体验金降低交易门槛
- 跟单功能推荐

【成长期】B级 → A级
目标：提升交易频次、增加入金
策略：
- 交易频次奖励
- 充值阶梯奖励
- 产品功能引导（从单一产品到多产品）
- 社群运营提升粘性

【成熟期】A级 → S/SS级
目标：提升资产沉淀、增加贡献
策略：
- VIP升级提醒
- 专属费率谈判
- 高净值活动邀请
- 1v1服务建立深度关系

【休眠期】任意层级 → 召回
触发条件：7天/15天/30天未登录
策略：
- 短信/Push召回
- 专属回归礼包
- 费率优惠限时体验
- 新功能介绍

【流失期】→ 放弃/隔离
触发条件：60天未登录且资产为0
策略：
- 最后召回尝试
- 数据归档
- 释放用户名/资源
```

### 4.2 分层触达策略

| 层级 | 触达渠道 | 触达频次 | 内容风格 |
|------|----------|----------|----------|
| SS级 | 专属客户经理 + 社群 + 邮件 | 实时/按需 | 尊贵、私密、定制化 |
| S级 | VIP客服 + 社群 + Push | 每日1-2次 | 高端、专属感 |

| R级 | 仅必要系统通知 | 最小化 | 简洁、无营销 |

## 5. 技术实现方案

### 5.1 数据架构

```
【实时数据流】
撮合引擎 → Kafka → Flink → 实时指标计算 → Redis
用途：实时更新AUM、爆仓提醒、快进快出拦截

【离线批处理】
业务数据库 → Data Warehouse (ClickHouse/Doris) → 标签计算
用途：T+1计算30日活跃天数、最大回撤、用户层级更新

【标签服务】
标签计算结果 → API → 运营后台/CRM/营销系统
```

### 5.2 核心数据表设计

```sql
-- 用户层级表
CREATE TABLE user_tier (
    user_id BIGINT PRIMARY KEY,
    current_tier VARCHAR(10) NOT NULL, -- SS/S/A/B/C/R
    tier_score INT, -- 综合评分
    last_evaluated_at TIMESTAMP,
    next_evaluation_at TIMESTAMP,
    tier_history JSON, -- 层级变更历史
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 用户指标快照表（每日）
CREATE TABLE user_metrics_daily (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id BIGINT,
    snapshot_date DATE,
    
    -- 资产指标
    wallet_balance DECIMAL(18,8),
    unrealized_pnl DECIMAL(18,8),
    net_deposit DECIMAL(18,8),
    
    -- 交易指标
    trading_volume_30d DECIMAL(18,8),
    trading_fee_30d DECIMAL(18,8),
    order_count_30d INT,
    avg_leverage DECIMAL(5,2),
    liquidation_count INT,
    
    -- 活跃指标
    active_days_30d INT,
    last_login_at TIMESTAMP,
    
    -- 质量指标
    abuse_score DECIMAL(5,2),
    avg_retention_time INT, -- 秒
    device_count INT,
    
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 用户标签表
CREATE TABLE user_tags (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id BIGINT,
    tag_name VARCHAR(50), -- Whale/HighLeverage/ChurnRisk/etc
    tag_value VARCHAR(100),
    expires_at TIMESTAMP, -- 标签过期时间
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 5.3 层级更新机制

**更新频率**
- SS/S级：每日更新（高价值用户实时监控）
- A/B/C级：每周更新（T+1批处理）
- R级：实时更新（风控触发立即标记）

**更新流程**
```
1. 数据采集：从各业务系统采集指标数据
2. 指标计算：计算综合评分和各维度得分
3. 层级判定：根据判定标准确定新层级
4. 变更通知：层级变更时触发通知（升级恭喜/降级提醒）
5. 权益同步：同步权益到各业务系统
```

## 6. 风控与防套利

### 6.1 层级操纵防范

| 风险场景 | 防范措施 |
|----------|----------|
| 刷交易量升级 | 引入"有效交易量"概念（持仓时间>5分钟） |
| 大额充值后立即提现 | 资金留存率指标，留存<24小时不计入 |
| 多账号协同 | 设备指纹+IP关联检测，关联账号同层级限制 |
| 代理自撸 | 代理线下用户返水比例自动降低 |

### 6.2 福利套利防范

| 风险场景 | 防范措施 |
|----------|----------|
| 薅签到奖励 | 签到门槛：净资产>10U或累计充值>50U |
| 返水循环套利 | 赠金交易不计入次日返水计算 |
| 多账号领福利 | 设备/IP关联检测，限制同一设备多账号福利 |
| 快进快出 | 资金停留<10分钟标记为R级，限制提现 |

### 6.3 降级保护机制

- **缓冲期**：层级降级前有7天缓冲期，期间发送保级任务
- **保级任务**：完成指定交易量/充值可维持当前层级
- **历史最高层级记录**：降级后仍保留历史最高层级标识，用于部分权益判断

## 7. 数据监控与效果评估

### 7.1 核心监控指标

**分层健康度指标**
| 指标 | 目标值 | 监控频率 |
|------|--------|----------|
| 各层级用户占比 | 符合模型设计 | 每周 |
| 层级升级率 | > 5%/月 | 每月 |
| 层级降级率 | < 10%/月 | 每月 |
| 高价值用户流失率 | < 2%/月 | 每月 |

**分层运营效果指标**
| 指标 | 说明 | 监控频率 |
|------|------|----------|
| 分层活动参与率 | 各层级活动参与比例 | 每次活动 |
| 分层福利使用率 | 发放的福利被使用比例 | 每周 |
| 分层ROI | 分层运营成本/带来的收益 | 每月 |
| 用户LTV分层对比 | 不同层级用户LTV差异 | 每季度 |

### 7.2 效果评估框架

```
【A/B测试设计】
- 对照组：不分层运营（统一福利）
- 实验组：分层运营（差异化福利）
- 评估周期：3个月
- 核心指标：留存率、交易频次、手续费贡献、LTV

【分层迭代优化】
1. 每月复盘各层级运营数据
2. 识别低效福利，优化或下线
3. 根据用户反馈调整分层标准
4. 季度性评估分层模型有效性
```
